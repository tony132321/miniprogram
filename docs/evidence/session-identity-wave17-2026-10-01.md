# 小程序同用户换会话身份隔离（2026-10-01）

## 问题与范围

登录令牌轮换而 `userId` 不变时，首页、发起、发现、活动详情、消息、活动记录及 API 分页的旧响应曾可能与新会话使用同一个前端身份键。本人数据和一次性跨页意图需要按**当前会话**隔离；活动主办和费用份额等业务判断仍须使用服务端的**原始用户 ID**。

修复后，首页、发起、发现、活动详情、消息和活动记录的页面防护把登录身份与 `sessionToken` 同时核对；开发模式继续按开发身份。首页构思、编辑目标、发现邀请码定位及举报表单上下文在跨页时使用一致的会话所有者；活动详情另取原始用户 ID 计算主办资格、成员称呼及费用行。活动、客服、公约三个举报入口仍传原始 `actor`，同时附带会话 `owner`；个人页只消费两者都匹配的上下文，旧版没有 `owner` 的内存上下文直接丢弃。旧会话完成的读取和旧卡点击不能填回新会话。

`utils/api.js` 对 GET 响应及 `/me/events` 分页使用会话身份栅栏，旧会话的成功或失败回调返回 `IDENTITY_CHANGED`。写入幂等指纹仍按稳定的用户 ID（缺失时退回令牌）识别：服务端以 actor、route、key 去重，同一已验证用户在未知 POST 后重新登录，需要复用原 key 安全续试；不同用户不会共用 key。普通 POST 不在 API 层改写成“未提交”，页面的动作结果由各自会话栅栏处理，避免掩盖已确认写入。

## 定向验证

- 首页待提交构思、发起页旧构思、发现邀请码定位、活动详情旧响应及旧主办操作均有新回归先失败后通过；登录主办的卡片详情仍用原始用户 ID 正确核对。
- 消息页旧通知、审核卡与延迟响应；活动记录旧响应和旧卡点击均有会话轮换回归，先失败后通过。
- API 延迟分页、普通 GET 及同用户未知写入续试／不同用户隔离均有回归；分页定向 **7/7**、API 相关定向 **18/18**。另独立复跑 API 分页 **7/7**、API 名称过滤用例 **5/5**。
- 页面合并相关 9 个定向文件 **65/65**、相邻页面 6 个定向文件 **60/60**、首页主办卡定向 **17/17**、WXML 路由绑定 **1/1**、类型检查和差异检查通过。文件组有重叠，数字不相加作为项目总测试数。

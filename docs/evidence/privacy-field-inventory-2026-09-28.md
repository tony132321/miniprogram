# Privacy field inventory: local code evidence

The deletion dry run and PRIVACY impact response now share `inspectPrivacyFields` in `src/privacy-field-inventory.ts`. Each entry names a table, column, class, structured ownership link, and a count of rows where that column is non-null. Queries use a fixed code whitelist and return no stored values. A count does not establish whether the value is personal information, how long it may be retained, or that it has been deleted.

The selected manifest covers direct account identifiers and tokens, host and activity text/JSON, notification detail and delivery metadata, consent notices, AI inputs/results/reviews, audit details, idempotency receipts, privacy quarantine payloads, and jobs whose top-level payload `userId` equals the account. For rows linked by an `OR` predicate, a populated column may belong to the other participant; the `ownerLink` value makes that scope explicit. JSON counts indicate that the column is present, including an empty object or array, not that every nested value has been classified.

Both responses explicitly list unresolved classes: identifiers embedded in unmatched text or nested JSON, provider copies, historical backups, infrastructure logs, and schema fields outside the selected manifest. `jobs.payload` only counts a top-level `userId` match. Production log and provider inventories remain external work; this output makes no retention or purge decision.

Historical ownership continuity: `getPrivacyRequestImpact` and `inspectPrivacyFields` now resolve request-bound event tombstones, dispute reporter pseudonyms, and quarantine source links after deidentification. The host predicate also verifies that the event's current `host_id` is the request's mapped tombstone. A deleted participant in another host's event therefore keeps their own registration and authored-content counts without inheriting that host's event, version, review, or safety fields. These are structured linkage counts; they do not search free text or JSON for hidden identifiers.

Local verification on 2026-09-28: `test/privacy-field-inventory.test.ts` passed 2/2. Its cross-owner regression created one event hosted by the deleted person and one hosted by another person, with the deleted person registered and authoring content in the latter. Before and after deletion/deidentification, impact counts were `hostedEvents=1`, `hostedEventVersions=1`, `registrations=1`, and `authoredContent=1`; post-deidentification field inventory retained one hosted event payload, one hosted event version payload, and one member registration identity. The other host's event and version were excluded. `dryRunPrivacyDeletion` and impact returned identical field inventories and no planted secret values. TypeScript `tsc --noEmit` passed. These are local synthetic checks, not a production database or processor inventory.

# RQ13 动态签到口令与扫码采用数据库时钟

正式 HTTP 签发签到口令、校验签到窗口、验证口令分钟桶及写入扫码时间现在使用数据库 `clock_timestamp()`。这与活动自动开始任务的时间来源一致，避免应用进程时钟超前时提前创建到场证据，或滞后时拒绝合法签到。已有的直接函数调用仍可显式传入测试时间，以保留单元测试的可控场景；HTTP 入口不再传入应用时间。

先新增超前／滞后应用时钟的 HTTP 回归测试并确认旧实现失败。修复后验证：窗口开放前口令签发与手工构造的提前扫码均返回 `CHECKIN_CLOSED`，没有写入 `checkins`；进入数据库时间窗口后，即使应用时钟滞后，签发的分钟桶落在数据库时间范围内且扫码生成 `SCAN` 证据。原有主办方权限、协办撤销、手动补记和完整活动流程测试已适配当前数据库时间窗口。

`pnpm test`：326/326 通过；`pnpm typecheck`、`git diff --check` 通过。微信开发者工具 0.3.11 连接本地开发 API，在隔离数据目录创建并确认 4 人活动：HTTP 签发口令剩余 56 秒，参与者扫码返回 `SCAN`；模拟器打开活动详情，运行时 `displayedCheckInToken` 为有效动态口令，`pages/event/event.wxml` 编译成功。[模拟器截图](wechat-qr-db-clock-2026-09-26.jpg)。这一验证使用开发身份和模拟器，不等于真机或正式域名验收。

# 小程序弱网重试幂等验证（2026-09-25）

小程序请求层为同一登录身份、请求方法、路径与内容保存未确定结果的幂等键。网络失败、HTTP 408 或服务端 5xx 后，用户重试同一操作会复用原键；成功或其他明确的 4xx 业务拒绝后释放该键。请求内容字段顺序不会改变匹配结果。这些不确定结果明确提示“提交结果尚未确认”，避免把丢失响应解释成操作失败。未确定键现写入小程序本地存储；模拟重建请求客户端及同一用户重新登录后可恢复。本地只存 SHA-256 请求指纹和幂等键，不存举报或申诉正文。无法持久写入键时，请求在发送前失败。

`test/miniprogram.test.ts` 使用真实本地 HTTP 服务模拟服务端已提交举报或建局草稿、小程序未收到响应：销毁并重建请求客户端后再次提交，仅各留下 1 条数据库记录，并返回原业务结果。另验证同一用户换令牌仍可恢复，账号或请求内容改变时不复用键，HTTP 408 与 3xx 响应仍视为结果不明，持久化失败不先发送请求，损坏的缓存键被忽略，SHA-256 与 Node 标准实现一致。全量 `pnpm test` **166/166**、`pnpm typecheck`、小程序请求脚本语法检查及 `git diff --check` 通过。该机制仍需真机弱网、设备断电、存储被清空及换设备恢复演练；没有把模拟丢包测试写成真实无线网络验收。

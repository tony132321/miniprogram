# 本人活动摘要与排序契约（2026-09-30）

`GET /me/events` 原先只返回标题、开始时间与身份状态，行程页因而无法展示真实场地和费用；列表还按随机 UUID 排序，补位机会和近期活动可能埋在后面。现在沿用原有活动审核可见性门控，向可见的本人活动补充 `venueName`、`feeMode`、`feeCapFen`；主办可看自己待审稿，成员与协办在待审期间仍仅见“活动审核中”，没有时间／场地／费用。排序优先可处理的 `OFFERED`，随后按可见的开始时间排列当前活动，历史活动倒序；隐藏的时间不参与排序，创建时间和 ID 用于稳定兜底。

`test/me-events-summary.test.ts` 通过 HTTP 层和实际数据库覆盖 UUID 与时间相反的三场活动、补位优先、无关账号空列表、主办／成员／协办在待审、已审、重大修改后重新待审三种状态的字段可见性。行程页定向用例补验真实摘要字段映射为场地与 AA 上限文案。相关服务端与小程序定向 **23/23**、类型检查和差异检查通过。这里是本地合成业务证据；尚未用新服务进程在微信开发者工具重新截图行程页，当前 `/me/events` 仍一次返回全列表，分页是后续性能缺口。

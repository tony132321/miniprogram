# 新主办方发布频率与人数上限（2026-09-28）

v3.1 PRD §16.1 要求新主办方有单独的发起频率及人数上限。原有每小时 10 次的统一 HTTP 限流和所有活动最多 12 人的字段校验，不能表达此要求。

第 53 版迁移新增持久主办方状态。真实活动主办方默认 `NEW`；目前试点的**临时可配置默认值**为每 7 天发布最多 1 场、单场最多 6 人，分别由 `NEW_HOST_WINDOW_DAYS`、`NEW_HOST_PUBLICATIONS_PER_WINDOW` 与 `NEW_HOST_MAX_PARTICIPANTS` 配置。PRD 未指定数字，最终数值须由产品及安全运营负责人批准；此本地默认值不是已批准的正式运营政策。合成 `is_test=true` 活动不消耗真实发布配额；HTTP 客户端不能自行声明活动为真实或测试。

直接发布与已审批 AI 动作发布共用核心事务守卫，先锁主办方状态行，再检查单场人数及最近发布数；同键重放不重新消耗配额。发布后的重大变更预览和最终写入也检查单场上限，防止先按 6 人发布再扩容。历史真实活动若缺可靠发布审计时间，按最近更新时间保守计入窗口，不把很早建草稿的时间当作最近发布的证据。具 `SAFETY` 权限的运营人员可在运营工作台输入主办方 ID、等级和核验原因，服务端保存复核人、时间、理由及审计记录；升级为 `ESTABLISHED` 只代表人工操作完成，不证明真实资质已核实。

新增 `test/new-host-limits.test.ts` 覆盖新主办方频率与人数拒绝、重放、并发、发布后扩容、AI 发布、旧活动时间口径及具名运营权限。第 53 版在本机 PostgreSQL 18.6 全新隔离库 `irl_r1_test_host_limits53_20260928` 完成迁移；`scripts/verify-postgres-host-limits.ts` 使用两个独立连接池同时发布，仅一场成功、一场返回限额拒绝，人工升级后被拒草稿可以发布；脚本退出码 0。另将已有第 52 版隔离库克隆到 `irl_r1_test_host_limits_upgrade53_20260928` 后运行迁移，版本升至 53，原有活动 1 条、AI 请求 2 条与源库数量一致。该测试仅用合成账号与活动，不代表真实资质审查、目标部署或运营政策批准。

本轮修改使四个既有指标测试中的多场真实活动夹具触发限额；明确给这些**合成指标夹具**设置已复核状态后，`test/metrics.test.ts` **23/23** 通过。随后主工作树 `pnpm test` **547/547**、`pnpm typecheck` 与 `git diff --check` 通过，修复前失败的 4 项均包含在全量通过结果中。

独立复核后，运营晋级入口增加真实用户存在性校验，避免提前给尚未建档的 ID 授予已复核等级；函数和 HTTP 路由均有拒绝用例。本人数据导出增加自己的主办方等级、复核时间和理由，不导出运营人员 ID 或他人记录。PostgreSQL 验证脚本改用运行时未来活动日期，并在全新第 53 版隔离库重跑双连接池竞争及晋级路径，退出码 0。修复后的定向新主办方与指标测试 **32/32**、隐私导出测试 **4/4**、全量 `pnpm test` **549/549**、类型检查与格式检查通过；这些仍是合成数据和本机环境证据。

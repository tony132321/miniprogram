# 公开活动招募总开关验证（2026-09-24）

按 PRD §16.3 与发布 P0「一键关闭能力」增加第 8 版迁移：单行数据库状态为 `OPEN` 或 `CLOSED`，由具备 `SAFETY` 权限的运营人员在工作台操作；关闭和恢复均要求 5–500 字原因，记录操作者、时间和审计行，同一幂等键重放不重复写入。

关闭范围：阻止新的公开活动发布、审核通过、报名/待定、主办预留、预留认领、补位接受、主办审批与成局；候补自动补位不会发出新邀约，新的公开分享来源与邀请轮换也被拒绝。公开邀请摘要对访客隐藏，陌生人不能读取公开详情，活动详情标记 `riskPaused`，旧补位通知不再标为可操作。已参与者及曾参与但已退出或被移除的人仍可查看详情，退出与安全/申诉渠道继续可用；邀请制活动继续运行。恢复总开关不会跳过活动本身的人工审核或已有单场风险暂停。

服务端单行共享锁覆盖新增公开席位及发布、审核事务；运营关闭使用独占锁，关闭提交之后不会有之前并发事务再新增公开招募。关闭状态持久于数据库，多连接池读取同一状态。

本地验证：`pnpm exec tsx --test --test-concurrency=4 test/*.test.ts`，103 项通过；`pnpm typecheck` 通过。第一次无限制并发运行中 `test/events.test.ts` 进程单独失败，随后该文件单独 5/5 通过，限制并发的全套 103/103 通过。

独立审查发现全局关闭时已移除成员会失去公开详情读取权；新增退出与移除后的回归断言并修复。后续全套 103/103 再次通过。

独立 PostgreSQL 18.6：全新空库 `irl_r1_test_gate2_20260924` 上执行 `scripts/verify-postgres.ts`；结果 `migrations=8`、`pools=2`、`confirmed=4`、`waitlisted=99`、`publicGateCrossPool=true`。两连接池先后关闭、读取、拒绝公开报名、恢复并接受公开报名；100 人争最后席位仍只增加一名确认者。此环境为本机测试库，尚未构成目标部署多实例、真实值守或真机证据。

后续补上关闭与恢复的站内通知：状态切换事务通过一次集合式 SQL 写入当时正在招募的公开活动主办方与当前报名者的持久任务；后台把任务转成站内通知，任务 ID 同时是通知 ID，重试不会重复写入。通知时间取取得总开关锁后的切换时间，旧任务晚处理也不会排在更新的恢复通知之前。只存放状态，不向用户泄露运营核查原因；没有正式微信模板时外部状态记为 `UNAVAILABLE`。待审核公开活动、草稿、邀请制活动及已退出/移除者不在本次通知快照中。`test/public-gate.test.ts` 验证收件人、幂等重放、任务重试与关闭/恢复顺序；全套 105/105 通过，类型检查通过。独立 PostgreSQL 18.6 全新空库 `irl_r1_test_gaterace_20260925` 上，`scripts/verify-postgres.ts` 输出 `publicGateNoticeCrossPool=true`、`publicGateConcurrentOrder=true`：跨连接池读取任务并生成站内通知，且让较早开始的恢复事务等待另一个暂停事务提交后再继续，验证恢复记录与通知时间仍排在暂停之后。本机验证仍不能代替订阅消息模板或运营复盘值守。

微信开发者工具模拟器使用本机测试号、独立 `.data/gate-notice-smoke` 数据库及开发身份 `host`：经本地 HTTP API 发布并审核一场公开活动，运营关闭招募后，后台任务生成站内通知；模拟器“我的”页显示“公开活动招募已暂停”([截图](wechat-public-gate-notice.jpg))。实际点击通知后，服务端 `read_at` 不再为空，运行时进入该活动详情，`event.riskPaused=true`([截图](wechat-public-gate-paused.jpg))。这是模拟器与本地 API 证据，尚未经过真机、正式微信登录或外部消息模板验收。

2026-09-25 补充并发时间顺序验证：PostgreSQL 时间戳有微秒精度，直接经 JavaScript `Date` 回写会丢失精度；快速关闭和恢复也可能落在同一毫秒。现由数据库保证 `changed_at` 严格递增，任务、站内通知和切换审计记录均直接沿用该时间戳。先让测试验证旧审计时间不一致，再修复；`test/public-gate.test.ts` 同时验证审计、任务与通知的精确时间一致性。全套测试 133/133 通过。PostgreSQL 18.6 全新库 `irl_r1_test_due_completion_auditfix_20260925` 双连接池并发验证再次输出 `publicGateConcurrentOrder=true`，并断言较早开始但后提交的恢复操作，其审计和通知均晚于暂停操作。测试实例已停止。

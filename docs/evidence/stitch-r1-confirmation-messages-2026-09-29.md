# Stitch R1 报名确认与通知操作（2026-09-29）

设计来源为用户提供的 `stitch_design_system_generator (2).zip` 中 PG05、`pg02_n_1`、`pg02_n_2`；在既有小程序和服务端上增量接入，页面不填设计稿里的假球友、人数、场地或通知。R1.1 的私聊、支付和公开找局仍按原产品范围保持未开放。

- PG05 报名按钮打开页内规则确认层，显示当前服务端版本、时间地点、人数、费用与取消规则；取消返回活动页。最终确认重新读取活动并核对身份、版本和邀请口令，提交仍走原报名接口；只有服务端确认席位才显示报名成功卡。通知深链只在活动成功加载后滚动到授权区块，协办审批与主办区块分别守卫。
- 通知页接入未读数、全部已读、活动提醒、互动消息与系统通知。`/me/notifications/open-all` 仅更新当前身份的未读通知，按每条首次打开保留脱敏业务事件，并以单个幂等键防重。提醒卡的入场凭证按钮打开本活动签到区块。
- 互动筛选从 `/me/approval-requests` 读取当前主办或有效报名审批协办可处理的真实申请，逐条“一键通过”仍由服务端复核身份、活动版本、截止、安全暂停、公开值守与容量；查看详情分别到主办或协办审批区。接口不返回设计稿中的虚构昵称。名额满时申请仍可见并可查看详情，但不显示可执行的一键通过；客户端方法也拒绝提交。安全暂停、全局关闭、公开值守不可用时不把申请显示为可审批；分页快照包含占位变化，其他审批者改变列表时返回 `QUEUE_CHANGED` 并从第一页重读。

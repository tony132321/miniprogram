# v3.1 活动成员屏蔽验收（2026-09-25）

来源：开发包 `AC-BLOCKING`，沿用 R1 已有活动内授权昵称、类似活动候选名单和个人页。第 21 版迁移记录发起人、目标成员、来源活动与撤销时间；没有引入公开个人主页。只有同场成员或主办方可从目标已授权的活动昵称发起屏蔽，不能屏蔽自己。屏蔽双方在该场活动的昵称列表互不可见；主办方与成员任一方向的屏蔽会把该成员排除在主办方结项后的类似活动候选名单。屏蔽不更改现有报名、签到或安全工单，页面不显示屏蔽原因。本人可在“我的”查看和撤销屏蔽；本人数据导出只含屏蔽记录与来源活动，不含目标账号 ID。

`test/blocks.test.ts` 先失败于缺少屏蔽行为，实施后验证：非成员不能屏蔽、双向昵称过滤、候选池过滤、撤销恢复，以及他人不能读取或撤销本人屏蔽。`test/miniprogram.test.ts` 验证活动页与个人页按钮调用现有 API。全量 `pnpm test` 233/233、`pnpm typecheck`、`git diff --check` 通过。

开发者工具测试号与本机 `127.0.0.1:3000`，独立 `.data/wechat-block-20260925` 合成库：`p1` 与 `p2` 各授权活动昵称。以 `p1` 身份在活动页实际点击 `p2` 的“屏蔽此成员”，页面昵称列表只剩本人、提示已屏蔽；服务端 `/me/blocks` 回读一条记录。返回个人页看到[屏蔽记录及撤销按钮](wechat-block-list-2026-09-25.jpg)，实际点击后页面与服务端列表均为空。再次点击屏蔽后，以 `p2` 身份打开活动页，昵称列表也只剩本人，见[活动页画面](wechat-block-event-2026-09-25.jpg)（该画面为 `p1` 屏蔽后的视图）。本机 API 在测试后已停止。

此证据限本地合成成员与模拟器。R1.1 的通用找局候选池、独立私人主页和正式微信真机均不在本次验证范围；正式 AppID、HTTPS 域名和受控真人试点尚缺。

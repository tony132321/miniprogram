# 首页主活动卡确认人数行（2026-10-01）

用户设计包 `stitch_design_system_generator (2).zip` 的 `stitch_design_system_generator/caper_2/screen.png` 与 `code.html` 在主羽球卡时间、地点下面放一行人数信息，示例为人物头像与“16人已报名”。原小程序 `pages/index/index` 主卡在该位置直接显示“配图仅作示意／查看详情”，缺少人数层次。

本轮只补这一处：首页已审核主办活动的主卡，从同场受权 `GET /events/:id` 回读 `stats.confirmed` 与 `payload.maxParticipants`，显示“已确认 X / 上限 Y 人”。必须同时满足当前账号、同场 ID、主办 ID、活动版本、审核通过、状态一致和有效整数；详情失败时保留原卡并隐藏人数。待审、普通成员以及权限或字段不明的卡保持列表原状，不因此增加成员默认首页的详情请求。左侧用中性装饰圆点还原参考图的人数行节奏，没有照搬虚构头像或“已报名”口径。整张主卡仍是一个按钮，点击进入同场详情。

## 定向验证

- 新增 `test/miniprogram-caper-home-feature-attendance.test.ts`。主办已审核卡真实详情回读与可见人数测试在实现前因没有详情 GET 先红；旧账号详情迟到测试也因没有详情 GET 先红。实现后新用例 **3/3**，连同既有首页状态与状态视图测试 **35/35** 通过。
- 待审主办、成员、缺少列表版本、字符串人数、主办 ID 不匹配、旧版本与详情异常均不展示确证人数；详情异常仍保留首页 `READY` 主卡。账号切换后的迟到响应不能恢复旧人数。类型检查、JS 语法检查与 `git diff --check` 通过。
- 按本批范围未运行全量测试，也没有重拍微信开发者工具或真机截图；这项代码与定向测试证据不能证明首页整屏逐像素 1:1。

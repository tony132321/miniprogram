# 运营后台真实浏览器交互（2026-09-27）

范围：PG12、RQ18、RQ19 的本地浏览器路径。使用 Google Chrome 153.0.8010.53（headless）与 Playwright 操作真实 `/ops` 页面，页面通过本地 HTTP 服务读取独立 PGlite 测试库。此前统一界面控制接口连续超时，不能作为点击证据；本次使用已有本地浏览器自动化运行时，未把模拟 DOM 单元测试冒充浏览器结果。

在空测试库 `.data/operator-browser-final-20260927`：实际输入开发运营身份 `ops` 并点击“刷新”，页面显示 0 条真实队列、空指标、公开招募开放状态，[页面截图](ops-browser-pg12-empty-2026-09-27.png)。切换无权身份 `guest` 再刷新，试点指标显示“无权限查看”，各队列明确标无权；切回 `ops` 后，仅拦截浏览器中的 `/ops/metrics` 请求模拟断网，页面显示“网络连接失败，请检查网络后点击刷新”，指标区域不再永久停留“读取中”；恢复网络并点击“刷新”后重新显示空态，浏览器无脚本异常。

同一页面实际输入原因并点击“关闭公开招募”与“恢复公开招募”、“暂停新增”与“恢复新增”。浏览器分别显示关闭与恢复结果；停止本地服务后直接回读数据库，两项开关最终均为 `OPEN`，四条 `PUBLIC_RECRUITMENT_CLOSED/OPEN`、`EMERGENCY_CLOSED/OPEN` 审计均由 `ops` 记录。演练仅作用于隔离测试库，没有修改真实运营设置。

在另一隔离库 `.data/operator-anomaly-browser-20260927`：插入一场标记测试的合成活动，以及同一合成用户在 24 小时内 3 次报名、2 次退出的审计线索。运营页面刷新后显示待复核条目，未查看证据前“记录复核”禁用；实际点击“查看行为记录”后显示 5 条行为并启用复核，[查看证据时截图](ops-browser-anomaly-review-2026-09-27.png)。选择“误报”、填写说明并点击“记录复核”，页面队列变为 0；停止服务后数据库回读 `REVIEW_REGISTRATION_ANOMALY` 的操作人、结论、原始次数与说明，队列查询也为 0。页面无脚本异常。

网络失败时的运营页文案先由 `test/operator-ui.test.ts` 复现旧版仅显示 `Failed to fetch` 且指标永久停在“读取中”，修复后定向测试与 Chrome 交互均通过。最终全量 `pnpm test` **434/434**、`pnpm typecheck`、`git diff --check` 通过。

这些结果验证本地 HTTP、真实浏览器点击、权限拒绝、断网恢复及上述两类实际写入路径。正式运营账号的密码与 TOTP、不同权限人员分工、浏览器兼容性、目标 PostgreSQL、正式 HTTPS 代理、真机及真人值守仍需目标环境验收；空队列和合成线索不能代表真实业务数量。

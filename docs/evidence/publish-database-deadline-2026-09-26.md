# RQ03 / RQ09 发布截止由数据库裁定

原草稿发布只用应用进程时间比较成局确认截止，并在最后的状态更新中没有再次检查。现先读取数据库 `clock_timestamp()` 拒绝已过期草稿；最后把截止谓词放入 `UPDATE events ... RETURNING`。若截止在检查后、写入前到来，事务保持草稿状态，不产生主办报名、任务、审计或招募入口。

先新增两个失败测试：应用时间落后于数据库截止时，旧实现仍发布；最终写入前截止变为已过期时，旧实现仍生成 `RECRUITING`。修复后两个测试通过，旧草稿状态和主办占位均保持不变。全量 `pnpm test` 为 330/330，`pnpm typecheck` 与 `git diff --check` 通过。

微信开发者工具 0.3.11 使用本地开发 API 载入隔离草稿，实际点击“生成发布前预览”，再通过页面运行时调用 `confirmPublish` 完成最终确认。活动详情回读同一 ID 为 `RECRUITING`、主办占位 1；[模拟器截图](wechat-publish-db-clock-2026-09-26.jpg)。模拟器正向链路不替代数据库截止竞争测试，也不代表正式账号或真机验收。

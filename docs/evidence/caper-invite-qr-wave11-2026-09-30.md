# RQ05 邀请二维码与发现页扫码（2026-09-30）

沿用已审核主办活动的现有分享资格与服务端可撤销、可过期邀请码，为 `_3` 活动邀请卡绘制真实二维码；二维码内容仅为当前服务端 `inviteToken`，不含活动 ID、手机号、精确集合点或自造 HTTPS 链接。邀请卡的可截图位置只显示城市和“具体地点请在活动详情核对”，具体场馆仍留在受权限保护的活动详情。不可分享状态不绘制二维码，原有复制口令和微信原生分享流程继续使用。

发现页现有邀请码区增加“扫描邀请二维码”按钮。扫描结果只接受本产品的 32 位 token，其他 QR 内容留在当前页并提示；合格 token 才进入现有 `pages/event/event?token=`，由服务端 `/i/:token` 校验有效性和撤销状态。扫描回调前后复核当前身份；发现页本人活动卡也拒绝切换账号后旧数据的点击。

隔离微信开发者工具测试 AppID、自动化端口 `9493` 与本机 API `127.0.0.1:3037` 实点：已批准合成主办的[邀请卡二维码](images/caper-share-invite-qr-wave10-2026-09-30.png)真实绘出；macOS 图像识别从模拟器截图解码的值与同一时刻服务端邀请码一致。发现页[扫码按钮](images/caper-discover-invite-scan-wave10-2026-09-30.png)可点击；模拟 `wx.scanCode` 回调时，非 token 内容被拒，合格 token 进入正确活动，页面异常 0。扫码成功路径使用模拟相机回调，不能替代真机摄像头测试。

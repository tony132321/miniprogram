# RQ19 风险暂停期间的分享意图挡板（2026-10-01）

隔离 PGlite 复现：邀请制活动发布并通过审核后，运营设置 `ACTIVE` 单场风险暂停；页面已提示不能分享，直接调用 `recordShareIntent` 却返回来源令牌，并在 `share_intents` 留下一条记录。活动仍为 `RECRUITING`，因此仅检查招募状态不能识别暂停。

分享意图的新请求与幂等重放现在同样在事务中锁活动行，核对主办身份、单场风险暂停、全局新增开关、公开招募开关、人工审核、招募状态和当前有效邀请码。放置及解除暂停也锁活动行；暂停已生效时返回 `RISK_HOLD`，不写入新的分享意图、审计或幂等结果。解除暂停后，被拒绝的新请求可用原键提交，既有成功请求可用原键取回同一结果且不重复写入。

复核还发现全局开关关闭时，旧成功请求会直接返回缓存来源；邀请码轮换不增加活动版本，旧请求键也会返回已失效来源。重放校验现在核对请求来源与缓存结果一致，并要求 `share_intents` 中的来源属于当前主办和活动，且邀请码摘要与当前令牌一致；旧来源返回 `SOURCE_STALE`，需重新准备分享。此校验不把分享意图算作实际投递或打开。

新增 `test/safety.test.ts` 的五项隔离数据库回归均先观察到 `Missing expected rejection`，修复后通过；单场暂停、全局开关、邀请审核和公开开关定向 **32/32**，分享 API 与业务事件定向 **2/2**，类型检查和所改文件差异检查通过。未运行全量测试；没有验证原生微信分享面板、真机转发或正式运营环境。

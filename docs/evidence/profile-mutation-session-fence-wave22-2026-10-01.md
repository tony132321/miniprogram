# “我的”页异步写入会话隔离（Wave 22，2026-10-01）

## 范围与根因

`pages/me/me` 的 GET 刷新已有会话身份核对，补位和导出也有局部保护，但两个授权开关及举报、申诉、屏蔽、隐私申请等 POST 完成后直接写页面状态。旧会话请求可以在新会话刷新后写入提示、授权状态，或再次刷新并清空新会话尚未提交的表单。`onShow` 原先仅按用户 ID 识别私有数据，同一用户换令牌时加载期还保留旧会话记录。

## 本地修复

- 页面异步动作统一捕获当前 `sessionToken`、`userId`、开发身份、页面访问代次、数据刷新代次及同类动作代次。只允许与发起时相同的当前会话更新页面；调用自身刷新后再核对该次刷新的代次。
- 活动提醒与类似活动邀请授权、解除屏蔽、打开通知、三类申诉、安全举报、个人信息请求和本人数据导出使用该守卫。旧成功和失败均不修改新会话提示或草稿，也不从旧回调触发新会话刷新。补位动作沿用已有会话核对。
- “我的”页重新显示时，如已加载数据属于旧令牌，先清除通知、活动、举报及表单等私有状态，再等待新会话读取。成功写入仍使用原有服务端幂等请求；本修复没有自动重发不确定 POST。
- 直接调用 `refresh()` 时也在启动新 GET 前核对完整身份，防止重试入口在同一用户换令牌后短暂展示旧记录。
- 两种授权写入按目的分别设置 in-flight 门控，开关在提交中禁用。后一次点击不会与前一次并发发送；第一次得到确定响应后，用户可再次切换。服务端 `setConsent` 没有提交序列版本，只有幂等键与 UPSERT，因此只依赖页面“最后响应生效”不足以保证服务端最终授权。
- 网络中断、408、5xx 或非确定的重定向响应保持开关锁定并显示“结果尚未确认”；用户点击专门的核对按钮后才重试与上次**完全相同**的授权 payload。底层 `api.js` 为该 payload 保留原幂等键，不会自动改发相反授权。身份清理会移除本页 pending 和核对按钮状态，旧回调不能清除新会话的 pending。

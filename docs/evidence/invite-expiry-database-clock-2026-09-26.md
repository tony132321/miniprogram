# RQ05 / RQ06 邀请有效期与报名写入

邀请入口原本按数据库时间过滤过期口令，但报名和待定意向在事务中用应用进程时间验证邀请有效期。现在两个事务均用数据库时间检查邀请，并在最终报名/意向写入语句内再次检查 `invite_expires_at`。活动行锁保持口令与活动版本稳定；公开活动和主办方本人不受邀请条件影响。

先复现应用时钟滞后时过期邀请仍可报名，以及邀请在最终写入前过期仍可占位；旧实现的两项测试均失败。修复后这些写入均拒绝且没有报名记录。PGlite 在本地测试中与宿主 `Date.now` 共享时钟，因此时钟偏差测试用数据库查询包装器分别模拟数据库与应用时间；写入边界测试由 SQL 的 `clock_timestamp()` 裁决。全量 `pnpm test` 通过 328/328，`pnpm typecheck`、`git diff --check` 通过。

微信开发者工具 0.3.11 在本地开发 API 下打开有效邀请，使用开发身份 `p4` 实际点击“本人报名或申请”，页面回读 `CONFIRMED` 与“报名状态已更新”；随后把模拟器开发身份恢复为 `host`。[模拟器截图](wechat-invite-clock-2026-09-26.jpg)。过期竞态只由数据库测试覆盖；本地模拟器不代表真机分享卡或正式网络验收。

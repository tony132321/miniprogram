# CAPER 通知中心按真实种类排版（2026-09-30）

对照用户提供的 `pg02_n_2/screen.png` 与 `code.html`，通知中心现在按真实 `kind` 区分卡片：活动提醒有顶部彩色条、右侧图形提示块及并排的入场区／活动详情按钮；规则或地点变更用绿色定位图标和详情内联入口；成局通知用绿色确认图标和状态条；待审核报名用粉色申请图标和靠右的查看／批准按钮。每个入口沿用现有服务端通知 ID、活动 ID、版本和权限校验。

当前 `/me/notifications` 响应没有可验证的活动封面、申请人头像、具体新地点或支付账单数据。因此右侧提示块是明确标注“活动提醒”的图形，不冒充某场活动照片；没有写入原稿的 Alex、Momo、Luna、地点、¥45.00、导航或结算功能。报名审批卡来自 `/me/approval-requests`，人数和批准结果仍以服务端为准。复核深链时另将主办结项通知定位到主办工作台、成员结项反馈定位到签到与反馈区；成功进入目标分区后才把通知标为已打开。

验证：先新增 `test/miniprogram-message-card-parity.test.ts`，观察到 2 条测试因缺少种类排版失败；实现及详情深链测试补充后，主代理复跑消息与相邻页面相关 **32/32**、`pnpm typecheck` 与 `git diff --check` 通过。此批尚未在微信开发者工具非空通知队列中复拍，因此卡片像素一致性、不同手机宽度和实点仍待最终模拟器复核。

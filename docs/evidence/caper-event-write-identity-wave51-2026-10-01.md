# 活动页写入口的会话与活动隔离（2026-10-01）

`pages/event/event.js` 已加载的旧账号活动详情在切换登录会话、活动或活动版本后，原先仍可能通过 `action()`、确认弹层回调或直接 `api.post` 发送写请求。尤其确认弹层在打开时展示旧活动，却在确认时重新读取页面 ID 和版本，可能把旧决定应用到另一活动。

本次在写入前核对非空页面归属会话、当前会话、页面活动 ID、已加载详情 ID、版本和 `READY` 状态。`action()` 只接受当前已有的活动、报名、人工补记、费用分摊和预留名额路径；未知路径拒绝。确认弹层固定打开时的上下文，返回时必须仍一致。报名和费用响应本身没有统一的活动 ID 字段，页面只对经当前活动接口成功读取的行附上本场 ID，再要求目标行 ID 和活动 ID 同时匹配；本人报名行仍核原有 `event_id`，人工补记核已有 `eventId`。协办授权/撤回、活动内昵称、屏蔽、事实问答、内容提交和签到码写入口也使用同一会话边界。响应返回后若身份或活动已切换，不再刷新旧私密内容或显示旧操作成功提示。服务端仍负责最终权限与版本校验。

# 单场风险暂停时间边界验证（2026-09-26）

服务端将暂停操作的开始时间判断改为数据库时钟，并在最终写入时再次核对活动状态及开始时间。解除暂停时，只有活动仍可招募、报名截止及开始时间未到、全局安全开关开放，且公开活动招募开关开放，才生成 `EVENT_SAFETY_RESUMED` 并尝试候补晋升；其他情形生成 `EVENT_SAFETY_REVIEW_CLOSED`。暂停与解除仍由原有运营权限、幂等命令和审计保护。

`test/safety.test.ts` 新增七个回归场景：解除时开始时间已过但状态任务滞后、解除时报名截止但状态任务滞后、暂停时数据库开始时间已过、暂停最终写入前活动开始、活动自身暂停招募、全局开关关闭、公开招募开关关闭。时间偏差通过数据库查询替身注入，最终写入竞争通过同一事务内改变活动开始时间复现；新增失败场景均在修复前观察到预期失败。正常解除流程沿用原有测试。单文件测试 11/11，全量测试 342/342，类型检查通过。

更新后的微信开发者工具 `wechatide` 0.3.11 已登录（`loginExpired=false`）。本地开发身份与隔离库 `.data/safety-hold-clock-20260926` 中发布邀请制合成活动 `dadb071b-43ba-4313-a2a1-397ed7867d52`，运营暂停后，模拟器打开活动详情，运行时回读 `event.riskPaused=true`，页面显示风险暂停提示，见[暂停截图](wechat-safety-clock-hold-2026-09-26.jpg)。运营解除后刷新同一页，运行时回读 `event.riskPaused=false`，见[解除截图](wechat-safety-clock-released-2026-09-26.jpg)；主办方站内通知回读依次为 `EVENT_SAFETY_PAUSED` 和 `EVENT_SAFETY_RESUMED`。本地 API 验证后停止。

模拟器验证只覆盖本地页面和 API；数据库时间偏差、截止瞬间及其他安全开关由自动化测试覆盖。解除操作非常接近活动开始时，通知可能在开始后才投递，因此接收者仍需以活动当前状态为准。正式微信身份、HTTPS 域名、订阅消息模板、真机和真人值守尚无验收证据。

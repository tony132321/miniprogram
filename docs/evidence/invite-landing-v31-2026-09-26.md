# T12–T13 邀请落地、报名与旧口令失效（2026-09-26）

复用现有邀请路由、活动详情、报名事务与四个小程序页面。`GET /i/:token` 的受限摘要现在返回数据库当前 `recruiting`、审核状态与最小活动字段组成的 `payload`，不包含主办 ID、成员名单或邀请口令。访客打开邀请时，详情若因未入会被拒，页面用刚从服务端读取的摘要展示活动，并用原口令报名；成功后刷新为有权限的当前活动详情。登录会话失效时，页面保留摘要和原口令，提供“登录并返回本活动”；无法读取活动或口令失效时，提供重试和“回到我的活动”。未报名者的协作、提问和签到入口按真实报名状态关闭；已报名者不再看到无效的重复报名或待定按钮。权限最终仍由服务端执行。

先加失败断言：邀请摘要缺少招募状态、页面登录失败后没有 `LOGIN_REQUIRED` 状态。修改后 `test/api.test.ts` 与 `test/miniprogram.test.ts` 定向 65/65、全量 `pnpm test` 258/258、`pnpm typecheck`、`git diff --check` 通过。页面自动化 fixture 验证摘要和口令穿过模拟的真实登录适配调用，最终报名动作仍携带原 token；这不是正式微信 code 交换证据。

微信开发者工具测试号与独立本机数据目录 `.data/wechat-invite-20260926`：创建一场邀请制活动，以开发身份 `visitor` 用 token 深链打开。页面读回 `loadState=READY`、受限摘要和可见的报名按钮；实际点击按钮后，页面读回本人报名 `CONFIRMED`，随后显示服务端当前详情及已确认 2 人。重新编译后以另一未报名开发身份打开，`canJoin=true`、`canUseCollaboration=false`，画面见[受限访客入口](wechat-invite-visitor-gated-2026-09-26.jpg)。原访客从活动 ID 回访时，`canJoin=false`、协作权限开启，见[报名后详情](wechat-invite-visitor-after-2026-09-26.jpg)。主办方撤销原口令后，旧深链刷新为 `ERROR` 和“邀请已失效”，且可返回“我的活动”，见[失效入口](wechat-invite-revoked-2026-09-26.jpg)。API 在验证后停止。

本机开发身份和模拟器不能证明正式微信登录后回原活动、真实分享卡转发、真机弱网或平台审核；这些门禁仍未完成。该活动和账号均是合成测试数据。

# R1 试点指标本地验证（2026-09-25）

依据：[PRD 第 21 节](/Users/tsb/Downloads/01_PRD_v1.0.md)和已确认的 [R1 功能规格](../superpowers/specs/2026-09-23-r1-functional-design.md)。本文件记录可由当前服务端数据核算的口径，不表示已有真实试点结果。

## 当前口径

| 项目 | 实现与边界 |
| --- | --- |
| 测试活动隔离 | 迁移 10 为活动增加 `is_test`，既有活动和开发身份新建活动默认测试。正式微信身份新建活动也默认测试；只有主办方已列入 `PILOT_USER_IDS` 时，新活动才标为正式候选，名单为空时不产生正式样本。客户端提交的 `isTest` 不改变标记；再约草稿继承来源活动分类。报表排除白名单外主办方或任一报名者所在活动；名单须由运营在受控试点前核验并配置。 |
| M01 WQCA | 只考虑已到开始时间、非测试且已有可访问发布版本的活动。按活动时区的自然周归组；使用首个可访问发布版本的最低人数：邀请制取该版本快照，公开活动取首次人工批准版本快照。必须已结项并有实际举行记录、主办方填报人数不少于最低人数、至少同等数量的独立用户签到记录（扫码或本人确认的人工补记），且有至少一名非主办方确认实际举行。结项争议、任何未解决的活动关联举报或活动风险暂停进入“待复核”，暂不计入合格数。 |
| M02 主办方 28 天复用 | 分母是首次可访问发布非测试活动后已完整观察 28 天的主办方；分子是同一主办方在 28 天内再次可访问发布非测试活动。公开活动提交审核或被驳回不算发布，首次通过人工审核才起算。另报告第二场已到结束时间的数量及其中达到上述可信完成条件的数量，未来活动不算完成失败。 |
| M03 贡献利润 | 返回 `UNAVAILABLE` 和缺少的实际收入、支付、AI、消息、按量云资源、直接人工、补贴、风险损失数据来源。AA 台账仅为参与双方记录，不能当作平台收入或支付凭证。 |
| D30 再参与诊断 | 用户首次参加一场非测试、已结束、主办方确认举办且有本人未争议签到证据的活动，扫码以本人首次有效签到时间、事后确认的人工补记以该场活动结束时间作保守代理，起算 30 个完整 24 小时日；在窗内另一场满足相同证据条件的活动中再次签到，才算再参与。主办方和活动任何报名者必须在已核验试点名单中，公开活动须已获批准。一个人只计一次，重复签到和同场多次记录不增加分子。分母只含完整观察 30 天的用户；不足 100 人时 25% 参考线不判定；第二场已签到但尚未结项或仍有结项争议时单列待补证据人数；首场参与仍待结项复核且已到 30 天的用户另列，不计入已证实分母。后者可能改变分母，故一律不判定 25% 参考线；前者只有可能改变结论时才保持未定。该口径由当前可验证证据定义，需在真实试点前由指标负责人确认，不代表平台默认活跃指标。 |
| 候补补位诊断 | 补位邀请按当前状态分列接受、过期、取消和未到期；成熟邀请确认率为接受 ÷（接受＋过期），见[独立验证](waitlist-offer-metrics-2026-09-25.md)。不能从邀请被创建推断通知已送达。 |
| 成局耗时诊断 | 从邀请制首次发布或公开活动首次人工批准到首条主办方成局审计，报告有记录活动数和中位分钟数，见[独立验证](formation-time-metrics-2026-09-25.md)。不把重复确认、最终举办或人工协调分钟混入该口径。 |

`GET /ops/metrics` 仅接受具有 `METRICS` 权限的独立运营账号；响应只有聚合计数、比例和缺失数据项，不返回用户或活动 ID。运营工作台展示每周合格／待复核／未达标数及成熟主办方样本。开发环境允许显式开发运营账号查看本地数据。

## 验证证据

- `test/metrics.test.ts` 覆盖旧数据保守分类、开发与正式身份赋值、名单为空时全部归测试、伪造客户端标记、再约继承、白名单外报名者排除、首次发布最低人数、活动时区周界、签到与独立反馈、争议和各类未解决活动举报、成熟 cohort 与二次活动、AA 不推断利润。
- `test/operator-permissions.test.ts` 覆盖 `METRICS` 专属读权限和聚合响应；`test/operator-ui.test.ts` 覆盖页面展示。全套 `pnpm test` 119/119 通过，`pnpm typecheck` 与 `git diff --check` 通过。
- 全新本地 PostgreSQL 18.6 库 `irl_r1_test_metrics_reviewfix_20260925` 完成迁移 1–10、双连接池读取、100 人竞争与指标合格样本核算，脚本输出 `pilotMetricsCrossPool=true`。合格样本的三名参加者都经正常报名流程登记，再加入明确的试点名单。
- 独立 PGlite 数据目录 `.data/metrics-ops-smoke` 启动本地 API，真实 HTTP `GET /ops/metrics` 返回空正式样本、成熟主办方 0、贡献利润 `UNAVAILABLE`；`GET /ops` 实际提供“试点指标”区块。该工作台是 Web 页面，不能以微信开发者工具的模拟器代替其测试。
- 追加公开活动发布口径回归：`test/metrics.test.ts` 覆盖待审提交不进入 M01/M02、驳回后提高最低人数并批准时 WQCA 使用批准版本、未获批二次公开活动不算复用。完整回归 `pnpm test` 126/126、`pnpm typecheck` 与 `git diff --check` 通过。全新本地 PostgreSQL 18.6 库 `irl_r1_test_public_metric_v2_20260925` 完成迁移 1–11、两连接池核算，输出 `publicPublicationGateCrossPool=true`。此前 119 项与迁移 1–10 记录属于当时版本；这次按新版代码重新验证。针对公开活动口径的只读复审未发现剩余 P1/P2。

追加到期活动证据完成率：按活动结束时间确定分母，给出待复核上下界，100 场以前不判断 70% 参考线；本地测试、运营页和 PostgreSQL 双连接池复核见[到期完成率证据](due-completion-2026-09-25.md)。此前测试数量属于各次修改时的快照。

追加 D30 再参与诊断：`test/metrics.test.ts` 先验证缺失指标，再覆盖 30 天观察窗、第二场签到在窗内而活动结束在窗外的边界、争议签到、事后人工补记、未结项回访待补证据、测试活动、名单外报名者、100 人成熟样本和 25% 参考线；`test/operator-ui.test.ts` 验证样本不足文案。新指标只在 `METRICS` 聚合报表返回人数与比例，不返回个人或活动标识。

独立复审指出三类会误判 D30 的边界：第二场截止前签到但结束在截止后、人工补记的确认时间晚于实际活动、首场参与待核验而改变成熟分母。现分别使用扫码时间与人工补记活动结束时间代理参与时间；未结项的第二场签到单列可能返回者，已到 30 天而首场仍待核验者单列并阻止提前判断 25% 参考线。最终复审未发现剩余 P1/P2。全套 `pnpm test` 138/138、`pnpm typecheck` 和 `git diff --check` 通过。全新本机 PostgreSQL 18.6 库 `irl_r1_test_d30_reviewed_20260925` 完成迁移 1–12、双连接池、100 人抢位和 D30 聚合跨池读取，输出 `pilotMetricsCrossPool=true`；其合成样本验证 4 位用户首次参加后未满 30 天时分母为 0，不能代表真实试点。测试实例已停止。

## 尚缺的上线证据

目前没有正式 AppID、真实试点账号和受控活动，因此**没有任何可声称达标的 WQCA、复用率、D30 或利润样本**。`PILOT_USER_IDS` 必须由运营核验并维护；名单遗漏会保守排除真实活动，误加未核验账号会污染试点统计。报表的 `eventCutoffAt` 限制活动开始时间和证据时间，但争议／工单状态按读取时的当前值评估，现有表没有足够的状态历史用于重放任意过去时点。PRD 要求的全流程业务埋点、完整直接人工分钟、支付与成本来源、成熟 D30 样本、目标环境负载和真实运营复核仍未取得。

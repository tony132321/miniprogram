# PG08 已结项反馈卡与“再来一局”入口（2026-10-01）

设计基准为用户提供的 `stitch_design_system_generator (2).zip` 中 `pg08/screen.png`（780 × 1684）及 `pg08/code.html`。底部白色反馈卡含两组各两项选择、粉色庆祝标记和蓝紫渐变“再来一局”按钮。原稿选择态是静态示意，原稿按钮仅有缩放动画；本次接入现有真实业务流程时没有预选反馈，也没有复用静态二维码或假倒计时。

活动页 `checkinSection` 在 **COMPLETED、有真实结项数据、非主办且本人报名 CONFIRMED** 时显示反馈卡。尚未反馈者可选“顺利举行了／未能举行”和“想！多来一些／暂时不”；两组仍由原有 `radio-group` 绑定到 `feedbackHeld`、`feedbackWouldRepeat`，无选择时不能提交。补充说明始终可见，已举办但有争议时可以选填；选择“未能举行”时变为必填，空原因在小程序层先拦截，服务端仍最终校验。切换选项不会丢弃已写文字。`提交独立反馈` 继续 POST `/events/:id/feedback`，客户端同时核对当前身份、活动 ID、结项与报名资格；成功后根据真实回读转为“已记录”状态。已提交者不再看到重复提交表单。

同一卡中的“再来一局”只写入带当前登录会话身份的单次 `irlCreateFreshIntent`，跳至现有发起页；不调用主办专属 `/events/:id/repeat`、不复制本活动、不创建或发布草稿。发起页在登录就绪后消费该意图；无待编辑内容时直接进入 IDEA。有未保存内容或排队待载入的草稿／活动时弹出确认：取消保留现有内容，确认仅清理本地待编辑目标并回到空 IDEA，服务端已保存草稿继续存在。意图属于其他会话时被丢弃。

独立审查补了两处边界：取消新局时保留已载入草稿／活动关联及可编辑状态；反馈 POST 迟到时核对账号、活动与刷新代次，不刷新下一账号页面，也不写入旧成功文案。并发点击只提交一次；网络结果不确定时冻结原选项，显示“重试原反馈”，保持同一请求体以复用 API 的持久幂等 key。

先失败后修复的定向用例覆盖：入口缺失、旧活动 ID 不得触发新建、未举办无原因被提交、已举办争议说明保留、原有发起编辑没有保护、同身份取消与确认、不同身份意图丢弃、藏在 IDEA 后面的日期修改保留、已载入草稿关联、反馈并发点击／不确定结果及旧会话回调。受影响 5 个测试文件合计 **125/125**，另 4 个相邻资料页测试文件 **24/24**；类型检查与差异检查退出码 0。本批未跑全量测试。微信开发者工具新版完成态实点和 39 屏同尺寸视觉验收尚未取得。

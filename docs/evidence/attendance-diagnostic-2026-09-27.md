# 报名截止 cohort 与实际到场诊断（2026-09-27）

范围：PRD 第 21.2 节“报名到场率同时报告截止时确认的 cohort 和最终实际参与，分别展示临时退出”，RQ18 与 T31。复用现有 `registrations`、`checkins`、活动版本和运营指标接口；未新增小程序页面或虚构报名人数。

第 42 版迁移新增 `registration_status_history`：数据库触发器对新增报名及真实状态变化追加记录，旧报名只在迁移时留一条 `legacy_snapshot`，不伪造此前的确认或退出时间。报名 ID 更新时历史关联同步更新。本人数据 JSON 导出自己的时间线；运营删除影响清单分别计数报名、活动及补位邀请的状态历史，仍标为需要策略复核，不执行自动删除。

`GET /ops/metrics` 新增 `attendanceDiagnostic`，只汇总符合试点隔离条件、且在报表 `asOf` 前已到结束时间的活动。以该时点活动版本的报名截止时间取报名状态：`CONFIRMED` 是截止 cohort；其中具未争议扫码或本人确认人工补记者为 cohort 到场。最终实际到场数单独统计相同活动和试点用户的合格签到，不把当前报名状态当作截止状态。截止后发生过本人取消或主办移除的人分别计数，即使后来重新报名，也保留那次临时退出线索。主办若本身报名且到场，按普通报名成员计入。旧记录或缺少截止时间使 cohort 不完整时，返回 `PARTIAL`、未知记录数和 `null` 比率，运营页不显示推断百分比。

测试先复现缺少状态表和运营显示，再验证截止两人确认、一人到场、另一人在截止后退出及重新报名，旧截止报表保持 `2/1`，临时退出另列；第 41→42 版升级不把旧的取消状态回填成截止状态；个人导出跨账号隔离；运营页完整与部分口径；FIFO 合成 ID 重排时历史外键仍完整。定向 32 项指标/迁移/导出测试及运营页、隐私清单定向测试通过；最终全量 `pnpm test` **433/433**、`pnpm typecheck`、`git diff --check` 通过。

微信开发者工具 0.3.11 使用新建隔离测试库 `.data/attendance-sim-20260927`，以开发身份 `p1` 打开“我的与通知”并实际点击“复制本人数据 JSON”。模拟器剪贴板回读 `registrationStatusHistory` 依次为同一报名的 `OFFERED → CONFIRMED`，两条均非旧库快照，也未出现其他成员报名；随后恢复 `host` 开发身份并停止本地 API。这证明本人的新状态时间线可经小程序导出，不证明真人报名、真机或运营浏览器交互。

目标 PostgreSQL 迁移和备份恢复、真实签到及至少三场受控活动仍待验。签到的后续争议标记、旧报名在迁移前的各次变化仍不能完整历史重放；该诊断不得用来宣称真实试点到场率达标。

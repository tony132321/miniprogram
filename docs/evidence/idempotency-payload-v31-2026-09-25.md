# v3.1 同键不同请求验收（2026-09-25）

来源：开发包 `AC-IDEMPOTENCY-MISMATCH`。沿用现有 `idempotency` 表、业务事务及 `Idempotency-Key`，第 20 版迁移只加请求哈希字段。服务端将 HTTP 方法、目标路径和规范化 JSON 请求体合成 SHA-256；JSON 字段顺序不改变哈希。事务领取原有幂等记录时保存哈希，重放同一请求返回首次结果，同键不同请求返回 HTTP 409 `IDEMPOTENCY_MISMATCH`。另一用户有自己的记录空间。旧记录无法恢复原请求内容，迁移后若被 HTTP 请求重用则拒绝，避免在未知内容上静默重放。

在 `test/api.test.ts` 中先加入草稿和通知同意两个失败用例：改动前不同标题的建局请求返回原活动（201），不同通知同意请求返回原结果（200），均未按规格返回 409。实施后，草稿、通知同意及报名三条 HTTP 回归验证同键同内容重放、同键改内容冲突、第二动作未执行以及用户隔离。报名路径复用现有 `command` 事务；草稿和通知同意原本各有幂等实现，现在共用领取/比对逻辑。迁移记录测试更新至 20 版。

全量 `pnpm test` 230/230、`pnpm typecheck`、`git diff --check` 通过。证据来自本地 HTTP/PGlite；微信真机和目标 PostgreSQL 环境中的网络重试仍待正式配置后验收。

# T09 主办方占位选择本地验证（2026-09-26）

原发起页默认勾选“主办方本人参加”，未作选择即可能在发布时给主办方占一席。现在新表单与未选择的旧草稿保持“待决定”；用户选择“参加，占用一席”或“不参加，不占席”后才形成布尔值。未选择时页面提示明确选择，服务端发布仍要求布尔值。部分草稿可先保存。已发布活动编辑时保留原值，编辑完成后的空表单重新回到待决定。

`test/events.test.ts` 验证未选择不能发布，明确选择不参加后发布的主办方报名数为 0；`test/miniprogram.test.ts` 验证初始状态、两个选择的载荷及保存草稿重开后 `false` 仍为 `false`。服务端不会根据活动总人数推定主办参加。

规则草稿提取器也将“主办方是否参加并占位”明确列为待确认项；原话“六个人”只影响最多人数，不再因页面默认值被解释为主办自动占席。`test/ai.test.ts` 2/2 通过。

微信开发者工具 0.3.11 模拟器中，发起页初始两个选项均未选中；实际点击“不参加，不占席”后页面状态为 `hostParticipates=false`，保存标题为“不占主办席位草稿”的部分草稿后，页面及独立 HTTP 读回均为 `DRAFT`、版本 1、`hostParticipates=false`。截图：[未选择](host-participation-before-2026-09-26.jpg)、[选择不参加](host-participation-no-simulator-2026-09-26.jpg)。

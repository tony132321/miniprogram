# v3.1 同秒候补排序验证（2026-09-25）

来源：开发包 T16 的 `AC-OFFER-FIFO-TIE`。复用已有报名、活动锁和 offer 事务，仅在报名表增加数据库分配的 `enqueue_seq`。释放席位时按该序号选择候补；退出后重新报名会取得新的序号，不会占用原队列位置。服务端序号由数据库 sequence 分配，不依赖客户端时间或随机报名 ID。

先写失败用例：把两名候补的 `created_at` 设为同一时刻、报名 ID 调整为与实际入队相反的字典顺序，原逻辑选错队首；改为 `enqueue_seq` 后选中先入队者。另验证候补取消后重新报名排到队尾。迁移回归验证旧报名按已保存的 `created_at,id` 顺序确定性回填。相关 16 个定向用例全部通过。

已应用不可变的第 23 版迁移到独立模拟器库 `.data/wechat-block-20260925`：回读迁移版本 23，8 条既有报名序号为 1–8。全新本机 PostgreSQL 18.6 测试库 `irl_r1_test_20260925_fifo_tie` 通过迁移 1–23、双连接池与 100 人争抢最后一席，脚本回读 `confirmed=4`、`waitlisted=99`；另在两连接池间模拟同秒候补、逆序 ID 和释放席位，回读 `waitlistTieCrossPool=true`。`pnpm test` 242/242、`pnpm typecheck` 与 `git diff --check` 通过；本机 PostgreSQL 实例已停止。

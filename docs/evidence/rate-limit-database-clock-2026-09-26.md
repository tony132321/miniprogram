# 限流窗口数据库时间验证（2026-09-26）

RQ19 的限流桶现在由数据库在原子写入时取时并计算窗口。微信登录、运营登录、邀请口令查询、活动详情读取、报名、建局及举报使用同一数据库时间规则；`Retry-After` 也由数据库时间计算。退出与举报不受报名限流阻断。

测试先用两个相差四小时的应用时钟对同一主办方连续发起 11 次建局请求：前 10 次未被限流，第 11 次返回 HTTP 429 和 `RATE_LIMITED`，数据库只留下一个主办方窗口桶。并发计数、窗口切换、运营违规列表、代理来源识别、报名限流后的退出与举报均通过 `test/rate-limits.test.ts`。`pnpm typecheck` 通过；`pnpm test` 为 345/345 通过。

更新后的微信开发者工具 `wechatide` 0.3.11 登录未过期，在独立本地库 `.data/rate-limit-clock-20260926` 与本地 API 下打开 `pages/index/index`，运行时读取 `loadState=READY`，API `/health` 返回 200，见[模拟器截图](wechat-rate-limit-clock-2026-09-26.jpg)。验证后本地 API 已停止。模拟器只验证了小程序页面与本地服务连通；跨应用时钟偏差的 429 行为由 HTTP 自动化测试覆盖，并非真机或正式微信环境验收。

# PG04-S 发布成功页口令入口（2026-10-01）

用户提供的 `stitch_design_system_generator (2).zip` 中 `stitch_design_system_generator/pg04_s/screen.png`／`code.html` 四宫格第三张是“复制小程序口令”。此前小程序发布成功卡只提供“分享邀请卡”，没有单独指向口令复制的卡片。当前 R1 已有活动邀请卡及真实邀请码复制功能，因此把发布成功页**第三张**管理卡接到同场邀请卡，不新增口令或假链接。已审核且仍可招募、安全状态开放时卡片称“复制小程序口令”；其他状态称“查看口令资格”。已审核卡**点一次**即进入邀请卡并自动触发该页实时核验后的复制；待审卡只展示分享资格，不自动复制。

邀请卡进入后重新读取当前主办活动与 `/system/safety`；复制动作在写剪贴板之前再次重读，只有 `APPROVED`、仍招募、未风险暂停、有当前 `inviteToken`，且当前时间早于报名截止时间时，才显示并复制真实邀请码。报名截止后即使后台尚未将 `recruiting` 置为 false，也按截止时间阻断；邀请卡停留至截止时主动清空可见口令和已准备的分享来源。待审态展示资格阻断，`display.inviteToken` 为空，不渲染复制按钮。原活动页的报名名单仍可从顶部成员入口、详情和主办工作台进入。原稿第二张“生成活动海报”和第四张“一键呼叫常聚球友”没有 R1 可用接口，当前保留公告和主办管理的真实入口；四宫格整体不能宣称 1:1 完成。

独立复核指出先前邀请卡的 `copyInvite()` 会直接使用页面缓存的 token。现已改为每次复制前再读取本场活动与安全状态，并以当前主办身份、页面代次和活动 ID 核对结果；轮换后复制新 token，审核／安全关闭或报名截止时停止复制，账号切换或其他刷新抢先完成时丢弃迟到响应。发布成功第三卡的资格同时受截止时间约束，点击当下会再次计算，不依赖先前渲染的布尔值。活动详情原生分享入口也按相同资格计算，截止或安全关闭时回退到普通首页路径，不外发过期 token。其分享回调、打开邀请卡和准备分享意图都核对页面活动 ID、页面活动主办 ID 与当前账号身份；账号切换但 `onShow` 尚未清理缓存时不外发旧主办口令。此处主办 ID 来自当前页面缓存，最终复制仍由邀请卡重读服务端验证。截止判断依据小程序设备时钟，服务端的分享意图接口另有截止时间校验。

# R1 本地控件与跨活动预留验收（2026-09-29）

本轮沿用现有 Project IRL 小程序和 API。独立审查发现并先用回归测试复现：A 活动页输入 B 活动的有效预留口令、版本号恰好相同时，可错误认领 B 的席位；若活动已结束，部分页面仍展示不能提交的操作；未登录的个人页仍展示隐私与举报操作；已发布活动编辑成功后返回发起页会停在无预览的确认状态；未登录消息页的互动筛选会请求受保护的审核队列。

修复与边界：

- 活动页认领提交当前活动 ID；服务端在事务写入前核对口令所属活动，对旧幂等键重放结果也核对活动 ID。不同活动返回 `RESERVATION_EVENT_MISMATCH`，不占席。原有合法认领流程保留。
- 活动页按业务状态收起已结束或不适用的报名、审核、普通移除、问答与内容写入、结项输入和免费活动 AA 费用输入，并显示当前不可操作的说明；重新确认只在有待确认版本且活动仍处于已审核招募状态时可点。截止时间和并发变化仍由服务端最终判断。
- 无正式会话且无本地开发身份时，个人页保留登录和公共导航，隐藏同意、导出、举报与申诉表单；消息页只显示登录提示，不显示消息筛选，筛选处理函数也不会请求受保护队列。
- 已发布活动编辑成功后用现有 `emptyEditor()` 复位发起页到想法输入状态，保留“新版本已生效”提示，并跳转最新活动详情。

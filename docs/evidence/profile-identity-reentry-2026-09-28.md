# 个人页重新进入时的身份隔离（2026-09-28）

个人页保留在小程序页面栈时，如果账号从别处切换，原先的通知、举报和其他本人数据可能在新账号请求返回前继续显示。页面现在以正式会话或开发身份及账号 ID 识别当前使用者；重新进入时若身份改变，先清空私有状态，再请求新账号的数据。迟到的旧请求由页面代际号丢弃。登录、退出和本地测试身份切换也同步更新该标识。

新增回归模拟旧账号请求未返回、切换新账号、随后两次响应逆序到达。测试在修复前因旧通知仍显示而失败；修复后确认新请求未返回时通知与举报列表为空，旧响应到达后仍只显示新账号数据。

本次工作树 `test/miniprogram.test.ts` 86/86、`pnpm test` 559/559、`pnpm typecheck` 和 `git diff --check` 通过。这里是页面逻辑的本地测试证据；真实微信账号切换、真机可见性及正式服务仍须单独验收。

随后在微信开发者工具自动化端口 `9420` 连接现有工程，启动隔离数据目录的 `DEV_AUTH=1` 本地 API。模拟器进入 `pages/me/me`，将旧账号通知与举报标记注入当前页面数据，再把开发身份从 `identity-smoke-old` 切到 `identity-smoke-new`，在同一页面实例触发 `onShow`。等待新账号加载完成后，页面返回 `READY`，身份为新账号，通知与举报列表均为零；自动化脚本退出码 0。首次断言紧接 `callMethod` 读取到 `LOADING`，因为该调用不等待异步页面请求结束；加入等待后复测通过。此回归验证页面实例中的切换与清理，不模拟旧请求晚到，也不代表正式微信登录或真机结果；晚到响应由上述本地定向测试验证。

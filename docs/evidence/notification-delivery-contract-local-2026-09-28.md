# RQ12 / T18 通知投递契约：本地实现证据

本变更复用现有站内通知、持久 `SEND_EXTERNAL` 任务、授权记录和运营跟进队列。通知种类在入队时写入用途、预定渠道、符号模板槽位和外发排程；worker 记录开始处理时间、提供方确定回执时间、引用编号及机器可读失败码。符号模板槽位不是已获微信批准的模板 ID。

当前可由现有告知授权外发的用途仅为 `EVENT_REMINDER`，且仍须有有效同意、最新活动状态和实际适配器。报名结果、候补、变更、成局、取消等通知不能借用该同意；worker 将其标记为 `PURPOSE_NOT_CONFIGURED`，站内记录仍保留，未打开记录进入运营待跟进。运营页显示状态、失败码、用途、模板槽位和排程，并记录人工处理。明确拒绝为 `PROVIDER_REJECTED`；超时或异常为 `UNKNOWN_REQUIRES_RECONCILIATION`，均不自动重发。`PROVIDER_ACCEPTED` 仅表示受理，不表示送达或已读。

合成适配器已覆盖受理、明确拒绝、状态不确定，以及旧活动提醒同意不能授权取消消息；既有授权撤回、账号停用、删除申请、活动失效、候补席位保留及人工跟进测试继续覆盖相关防线。整合邀请审核后的定向测试 29/29、全量 `pnpm test` **509/509**、`pnpm typecheck` 和 `pnpm audit --audit-level high` 通过。这些均为本地合成数据证据。

本机 PostgreSQL 18.6 的全新空库 `irl_r1_test_notify49_20260928_a` 执行 `scripts/verify-postgres.ts` 退出码 0：49 个迁移、两个连接池、100 人争最后一席，最终确认 4 人、候补 99 人，输出的跨池隐私删除保护、通知人工跟进和其他既有布尔检查均为 `true`。另将第 48 版的合成测试库复制到 `irl_r1_test_notify49_upgrade_20260928_a`，双连接池并发运行 `scripts/verify-postgres-notification-upgrade.ts`：462 条旧通知及其结果未改写，447 条已有外发任务的通知补齐用途、渠道、模板槽位和排程。两个库都仅在本机回环地址上使用。

发布缺口：正式 AppID、可用订阅模板、微信侧授权与回执、真机和真实运营跟进仍未验证。生产入口没有注入真实通知适配器，因此仍不会发出微信消息。另有独立的 `AC-JOBS` 冲突：当前通知 worker 在持有业务事务锁期间调用适配器；本变更保留现状，不能据此宣称满足规范中的“外部网络调用不持有业务长事务”，需另行设计与验证 fenced claim / 状态复核流程。

整合至邀请审核 schema 48 后，本通知契约迁移编号为 `0049_notification_delivery_contract.sql`；此前分支的 498/498 结果仅为独立工作树证据。

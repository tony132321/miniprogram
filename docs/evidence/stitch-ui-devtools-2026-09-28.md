# Stitch UI 接入与开发者工具核验（2026-09-28）

## 范围与实现

以现有 Project IRL R1 服务端与页面逻辑为基础，接入用户提供的 Stitch 设计包的视觉语言和导航结构。首页、发现、发起、消息、我的组成五个底部入口；城市选择、关于、活动详情是独立页面。活动详情里的报名、公告问答、签到、费用、主办工作台复用原有接口与权限守卫；发起页保留 AI 建议、手动填写、草稿、预览、最终确认和变更预览。视觉素材落在 `miniprogram/assets/stitch/`。R1 原验收包只有三个主要入口，五入口是此后用户明确要求接入完整 UI 的范围调整；公开找局、私聊等尚未开放的能力在页面上明示状态，不把展示元素伪装成可用服务。

## 本地微信开发者工具实际点击

环境：微信开发者工具 2.02.2609231 RC，iPhone 17 模拟器，`DEV_AUTH=1`，独立本地 PGlite 数据目录，API 为 `http://127.0.0.1:3000`；项目路径 `/Users/tsb/Documents/小程序`。本地合成身份 `identity-smoke-new`，合成草稿 `8b077ad9-77f9-484a-b157-a3e64ad3f3d8`，标题“UI 验收羽毛球局”。该草稿由本地 HTTP `POST /events` 创建，用于验证小程序读取和页面导航，不能算小程序表单创建端到端证据。

实际点击与回读：

1. 首页四个分类中的“我组织的”显示服务端草稿；点击草稿卡进入活动详情，草稿状态和待确认信息与服务端记录一致。
2. 活动详情海报修正后英文标题分为两行，未见先前横向溢出；六个分区入口成为原生按钮。点击“主办工作台”后滚动至对应分区，显示人数、场地核对和“继续编辑草稿”。
3. 底部“发现”“消息”“我的”“发起”可打开对应页面。发现页显示“公开找局暂未开放”和邀请入口；消息页显示本人站内通知空态及私聊暂未开放；发起页手动填写入口和缺少主办参与信息时的发布前校验提示曾实际触发。
4. “我的 → 关于 Project IRL → 发现活动 → 城市选择 → 北京”逐步点击成功，发现页城市标签回填为“北京”。此前普通 `view` 承载的导航/分类项在当前模拟器点击中未触发，改为原生 `button` 后复测成功；发起页的“我的活动”和灵感选项也改为原生按钮。
5. 开发者工具当前调试器显示 0 Errors；Console 中警告为本地未校验合法域名、工具资源预加载和 `reportRealtimeAction` 不支持。本地开发配置不能作为 HTTPS 合法域名或真机网络验收。

## 证据边界与待办

这次记录证明上述具体页面和点击路径在本地模拟器运行。所有 UI 控件仍须按其所在业务状态验证，尤其是真机输入、分享、扫码、微信登录、订阅消息和正式域名。当前缺少正式 AppID、HTTPS API 合法域名、外部通知模板/提供方、真机与三场受控真实活动；不能据此宣告 R1 完整 UAT 或上线通过。旧版活动整链路的模拟器及 HTTP 证据仍列在验收矩阵中，不被这次设计接入覆盖。

发布预检 `pnpm preflight:release` 在本候选明确失败：API 尚非已配置合法域名的公开 HTTPS 地址，正式配置仍有开发身份，项目 AppID 尚未替换本地测试号，开发者工具项目和本机私有配置仍关闭合法域名校验。预检失败是上述外部配置缺失的预期阻断，不计为代码测试通过。

2026-09-29 复审补充：发起页两个 HTML `<br/>` 改为 WXML 原生分行元素，表单返回想法页后复位顶部滚动位置。开发者工具实际点击“直接手动填写 → 返回想法输入”，首屏重新显示完整标题和灵感按钮；CLI 再次预览编译成功（1,898,741 字节），类型检查通过。此补充不扩大前述端到端覆盖范围。

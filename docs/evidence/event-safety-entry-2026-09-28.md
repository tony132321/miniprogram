# 活动页安全求助入口（2026-09-28）

v3.1 PRD §16.3 要求活动页提供投诉入口，并提示遇到人身紧急危险时离开风险地点、联系当地应急服务。此前活动详情显示主办方和地点，但举报工单入口只在“我的”页，需要手动填活动 ID。

现有活动页增加简短紧急提示和“举报与求助（关联本活动）”按钮。点击后跳转到已有的“我的”页举报表单，使用只在本次小程序进程内有效的一次性上下文填入活动 ID；仅当跳转前后为同一账号才填入，读取后立即清除。举报仍由本人主动写描述和提交，走既有服务端鉴权及工单流程；入口不自动创建举报，也不宣称平台提供应急救援。

小程序定向测试先因缺少 `goToReport` 失败，补齐后通过；测试覆盖从活动页到本人表单、工单提交带入该活动 ID、一次性消费和切换账号时清除。`test/miniprogram.test.ts` 全文件 **84/84**、`pnpm typecheck` 通过。微信开发者工具 `cli preview --project /Users/tsb/Documents/小程序` 输出 `✔ preview`，测试 AppID 包体约 346.2 KB。

本次没有在模拟器实际点击该按钮；电脑锁屏阻止可视操作。正式 AppID、真机与真人值守未验证。PRD §16.1 的新主办方专属频率及人数上限是另一个未实现缺口，不能由统一 `host-create` 限流冒充完成。

# 候补邀请诊断的历史状态（2026-09-27）

范围：T31 候补邀请诊断、RQ08 与 RQ18 本人数据。此前 `getPilotMetrics(asOf)` 用邀请的当前状态解释过去：截止后才被接受的邀请会提前进入旧报表的“已接受”。第 40 版迁移新增按数据库时间追加的 `offer_status_history`，触发器覆盖所有插入和状态更新；同值更新不增加状态记录。指标按截止时间选择当时最后一条状态，再按邀请到期时间区分仍有效与已经过期。

新测试先复现旧报表把事后接受计作已接受的失败，再验证更新后旧报表仍为 `ACTIVE`、新报表为 `ACCEPTED`。升级测试模拟旧库中的一条已接受邀请和一条未知状态：迁移在当时各保存一条 `legacy_snapshot`，但在迁移前的 `asOf` 两条都列为 `unclassified`，不伪造旧接受时间；迁移后的报表保留已知状态，并将未知状态继续列为未分类。状态表不强加新枚举约束，以免无法升级含未知历史值的库。

本人数据导出增加自己的邀请状态时间线，仅通过本人报名记录关联，不暴露另一参与者的邀请 ID。`test/metrics.test.ts`、`test/db-migration.test.ts`、`test/privacy-export.test.ts` 定向运行 27/27 通过；全量 `pnpm test` 427/427、`pnpm typecheck` 和 `git diff --check` 通过。这里的“已发”仍取邀请 `created_at`，没有外部微信送达证据；老记录在迁移前的细分状态无法恢复，目标 PostgreSQL 和真机仍待验。

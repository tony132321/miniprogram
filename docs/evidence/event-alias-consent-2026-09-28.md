# 活动内昵称的逐场展示授权：本地与 PostgreSQL 验证（2026-09-28）

基于 `46a5030` 的独立工作树增量实现。第 50 版迁移为活动内昵称保存告知版本，并另存逐场授权与撤回历史（目的、活动范围、告知版本及原文、数据库时间、来源）。告知原文复用小程序原有的“仅在本活动内展示的昵称（可选）”，没有编造正式法律告知。旧库昵称保留给本人导出，但版本为空；升级后其他成员默认看不到，所有人只能在本人重新输入并提交当前版本后看到新昵称。提交缺失或旧版告知返回 409，不改变旧记录。本人撤回在同一事务删除可展示昵称并记录撤回，活动提醒和类似邀请授权不受影响。

删除申请的即时保护仍会移除昵称；第 50 版同时记录来源为 `DELETE_REQUEST` 的撤回。旧记录没有原始告知版本时写明 `LEGACY_UNVERSIONED`，不补造先前同意。本人导出包含自己的昵称授权历史，后端运营隐私影响清单增加该历史的数量。主工作区运营影响页也补上“活动昵称授权历史”的数量展示，`test/operator-ui.test.ts` 定向 43/43 通过；页面仅展示影响数量，不展示授权记录正文，也不代表正式删除策略已经确定。

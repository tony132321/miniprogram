# 本人数据导出凭据数据库时钟验证（2026-09-26）

复用现有 `/privacy/exports` 短时凭据及个人页入口。此前凭据签发和下载过期判断使用应用进程时间；应用时间滞后时，数据库已到期的下载路径仍可能返回本人数据。现在签发时直接以数据库 `clock_timestamp()` 加 10 分钟写入 `expires_at`，下载时在同一条数据库查询中判断 `expires_at<=clock_timestamp()`。仍要求当前本人身份，其他账号读取同一路径保持 404，到期本人读取返回 410 `EXPORT_EXPIRED`；原有幂等签发和动态生成 JSON 的方式不变。

HTTP 回归先在旧实现上观察到两次预期失败：应用时钟落后 1 小时时签发时间早于数据库预期；修正签发后，旧下载判断仍把数据库已过期的凭据放行。修复后，时钟偏差、本人领取、跨账号拒绝和过期拒绝的目标测试通过；全量测试 344/344、类型检查通过。

更新后的微信开发者工具 `wechatide` 0.3.11 使用测试号、本地开发身份和隔离库 `.data/export-clock-20260926`。在“我的”页实际点击“复制本人数据 JSON”，运行时回读“本人数据 JSON 已复制，可粘贴保存。”，见[模拟器截图](wechat-export-clock-2026-09-26.jpg)。本地 API 停止后回读隔离库，凭据数量为 1，`expires_at-created_at` 约 600.004 秒。数据库里的合成用户数据没有用于真实个人资料验收。

原有 `/privacy/export` 直接认证导出接口仍保留供兼容；10 分钟有效期约束的是凭据下载路径，并非所有已认证导出访问。该证据只覆盖本地数据库、HTTP 和开发者工具模拟器；正式微信身份、HTTPS 域名、真机复制与文件保存，以及注销删除执行流程仍待验。

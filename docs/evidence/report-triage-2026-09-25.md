# 举报工单优先级与分页验证（2026-09-25）

PRD §16.2 要求举报进入人工处置队列。原运营接口只按创建时间倒序返回最近 100 条；当已结案工单较多时，较早提交但仍未处理的安全举报可能不在页面上。本次按“未结案安全类 → 其他未结案 → 已结案”排序，未结案队列内先显示较早的工单，已结案按最近时间排序；每页 100 条，运营人员可继续加载，页面同时显示总数。服务端保持 `REPORTS` 权限检查，并拒绝无效偏移量。

这里的 `SAFETY` 是用户选择的举报类别，仅用于保守地优先呈现，**不是已核实的高危等级**。排序不会自动处罚被举报者，也不代表已有 15 分钟人工响应、用户结果通知或运营值守。复审发现单纯偏移量分页在新增安全举报或另一运营人员结案时可能跳过工单；后续页现在携带首屏的数据库队列快照摘要。任何工单增删或排序字段变更都会使旧快照返回 409，工作台自动从第一页刷新；刷新期间旧翻页入口立即停用。正式值守告警和处理时限留痕仍未实现。

`test/report-queue.test.ts` 使用 105 条未结案安全举报、1 条普通未结案和 120 条较新的已结案记录，验证三页覆盖全部 226 条、不重复、优先级与无效页码拒绝；另外验证新增安全工单和状态变更均拒绝旧页。`test/operator-ui.test.ts` 验证工作台加载后续页、队列变化时自动重读第一页、刷新期间不能使用旧翻页状态。全套 `pnpm test` 143/143 通过；修正刷新结果提示后定向运营页测试 14/14、`pnpm typecheck` 和 `git diff --check` 通过。独立 PostgreSQL 18.6 全新库 `irl_r1_test_report_queue_final_20260925` 迁移 1–12、双连接池、100 人抢位与举报排序分页跨池读取和新增安全举报后的旧快照拒绝通过，脚本输出 `reportQueueCrossPool=true`。测试实例已停止。独立复审未发现剩余具体 P1/P2。

视觉参照为用户提供的 Stitch ZIP 中 `caper_1`、`pg10_a_edit_profile` 和 `pg10_e`。微信开发者工具使用测试 AppID `wxbbcab69099026d3f`、本地 API `http://127.0.0.1:3000` 和本地合成身份 `host`。这些实点证明当前模拟器里的指定路由和数据绑定，不构成 39 屏逐像素通过、正式 AppID 或真机验收。

## 实点与截图

1. [活动记录筛选与长页中段](images/caper-profile-activity-filter-2026-09-30.png)：`GET /me/events` 在本次身份下返回 2 条本人活动；“我发起的”筛选保留这 2 条，卡片标题、时间和状态来自服务端摘要，照片标为示意配图。点击主办活动卡进入 `pages/event/event`。新增“我的发起活动”预览卡同样以真实活动 ID 进入详情；“查看全部”进入活动记录页并预选“我主办的”，包括终态主办记录（终态路径由聚焦测试验证，当前截图没有终态活动）。“已收藏”显示待开放，不显示原稿中的虚构收藏。
2. [邀请横幅进入资格页](images/caper-profile-share-entry-2026-09-30.png)：本次身份只有 1 场本人招募活动，横幅直接进入 `subpackages/activity/share/share`。该场合成活动尚未通过审核，邀请页按服务端资格显示“暂不能分享邀请”；没有产生可用邀请码，也未声称已发送微信邀请。聚焦测试另验证 0 场时进入发起页、2 场时进入首页“我组织的”供用户选择，没有按 UUID 默选一场。
3. [候补通知焦点](images/caper-profile-notice-focus-2026-09-30.png)：写入一次性本机意图 `irlProfileFocusIntent=noticeSection` 后进入“我的”，意图被消费，账号与安全操作展开，滚动定位到吸顶栏下可见的“站内通知”。本次真实通知数为 0，显示空态；接受或拒绝补位仍须依据真实通知和有效期在该区域操作，本次未做虚构补位。
4. [协议页隐私请求深链](images/caper-profile-legal-privacy-2026-09-30.png)：`pg10_e` 的“管理账号与隐私请求”以及 `pg10_a` 的“申请注销账号”均在切到“我的”后展开并定位“个人信息请求”表单。按钮可见“复制本人数据 JSON”“申请导出”“申请注销或删除”；本轮只验证导航与可见性，没有提交注销或删除请求。

“我的”页面还把开发身份切换移到折叠操作区，保持非开发身份未登录时的微信登录入口；通知、资料、隐私、帮助、社区公约和关于菜单均指向现有路由。主理人工具的中心入口传递首页“我组织的”页签意图；“我的发起活动→查看全部”进入包含终态的本人活动记录。未登录的协议隐私深链会在本次个人页访问内等待登录成功，然后打开请求表单；登录失败或离开会清除待处理意图，此路径仅由聚焦测试验证。没有为头像、兴趣、勋章、收藏、相册或全局个人资料增加虚构数据。

# T12 发起页草稿读取与版本冲突恢复（2026-09-26）

复用原生发起页和现有草稿、活动变更接口。活动详情跳转发起页时，待编辑 ID 现在与当前身份一起暂存在本地；只有服务端草稿或活动规则成功读回后才清除。断网时显示明确错误、重试和返回“我的活动”，且不允许把空表单当作新草稿提交。账号变化时丢弃其他账号的旧编辑目标；新账号刚发起且绑定自己的目标可以继续读取。

原有服务端 `expectedVersion` 已拒绝旧版本写入。页面现在对 `VERSION_CONFLICT` 清空旧预览并提示“本地修改尚未保存”，由本人明确点击后才重新载入服务端当前版本，防止静默覆盖另一个窗口的变更。新流程沿用原活动读取接口，不建立副本或影子版本。

先加失败用例：断网后 `editorLoadState` 缺失、交接 ID 已被删除；旧版本写入后缺少可执行的冲突恢复状态。修复过程中还定位到跨账号迟到请求可能复用旧编辑 ID，故补身份绑定和对应测试。`test/miniprogram.test.ts` 定向 44/44、全量 `pnpm test` 261/261、`pnpm typecheck`、`git diff --check` 均通过；开发者工具 `compile_wxml pages/create/create.wxml` 成功。

微信开发者工具测试号、本机独立合成目录 `.data/wechat-invite-20260926`：API 停止时，从一场真实保存的活动进入编辑页，页面读回 `editorLoadState=ERROR`，本地编辑 ID 与所属开发账号保持不变，见[断网页面](wechat-editor-offline-2026-09-26.jpg)。重新启动同一目录 API 并执行 `retryEditorLoad` 后，读回原活动当前版本 2，交接 ID 与所属账号从本地清除，见[恢复页面](wechat-editor-recovered-2026-09-26.jpg)。另建独立草稿，在编辑页停留时从 HTTP 以同一主办身份将服务端版本 1 更新到版本 2；旧页面保存收到 409 并显示[版本冲突提示](wechat-editor-cas-conflict-2026-09-26.jpg)。明确执行 `reloadConflict` 后，读回服务端版本 2 和新标题，原草稿未被旧页面覆盖。API 在验证后停止。

这些结果是本机模拟器和合成身份验证；正式微信会话、跨设备冲突、大字体与真机断网恢复仍待验。

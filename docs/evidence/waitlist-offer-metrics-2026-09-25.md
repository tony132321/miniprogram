# 候补补位邀请诊断（2026-09-25）

`GET /ops/metrics` 新增只含聚合数的 `waitlistOfferConversion`：统计已核验试点名单内、非测试且已对外发布活动所产生的补位邀请。返回已发、已接受、过期、取消、未到期和未知状态数量；“成熟邀请确认率”只用已接受 ÷（已接受＋过期），不把尚未到期或因其他原因取消的邀请当作拒绝。`ACTIVE` 但在统计截止时已过期的邀请计入过期，即使后台任务尚未更新状态。该指标是候补链路诊断，不是消息已送达率或活动完成率。

`test/metrics.test.ts` 先验证缺失指标，再覆盖五种邀请状态、到期未运行任务、测试活动排除、名单外报名者排除和响应不含活动 ID；`test/operator-ui.test.ts` 覆盖工作台显示分母。另在本机 PostgreSQL 18.6 全新库 `irl_r1_test_waitlist_offer_crosspool_20260925` 运行迁移 1–16、两个连接池和 100 人抢位后，从另一连接池读取已接受邀请的聚合结果，输出 `waitlistOfferCrossPool=true`；测试实例随后停止。

全量 `pnpm test` **179/179**、`pnpm typecheck` 与 `git diff --check` 通过；PostgreSQL 验证还返回 `migrations=16`、`pools=2`、`confirmed=4`、`waitlisted=99`。

邀请状态按读取时的当前值解释；数据库没有每次状态变更时间，不能把过去任意 `asOf` 当作可精确重放的历史确认率。没有微信消息模板、实际送达回执或真实试点样本，本指标目前只能验证计算链路。

2026-09-27 更新：第 40 版迁移开始记录状态变化，新生成邀请可按 `asOf` 重放；旧邀请在迁移前仍没有可靠状态时间，按未分类处理。见[历史状态验证](offer-history-asof-2026-09-27.md)。

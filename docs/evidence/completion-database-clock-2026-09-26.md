# 活动结项数据库时钟与最终写入验证（2026-09-26）

RQ13 结项原先使用应用进程时间判断活动是否结束，并把这个时间写入结项记录。应用时间超前时，即使数据库认为活动尚未结束，主办方也可能提前把活动标为 `COMPLETED`。当前实现以数据库时间做前置检查，结项记录通过带活动结束时间条件的 `INSERT ... SELECT` 写入，写入前再次核对数据库时间、活动状态和结束时间；`completed_at` 也由数据库生成。若条件失效，整个幂等命令回滚，不留结项记录或已结项状态。

两条新回归在旧代码上失败：HTTP 应用时间超前时曾返回成功；同一事务内在最终写入前把活动结束时间移到未来，旧代码仍提交结项。修复后，全量测试 344/344、类型检查通过；HTTP 测试还验证应用时间落后时数据库已结束的活动可正常结项，且 `completed_at` 不早于活动结束时间。既有结项测试继续覆盖“实际举办”“未举办”、独立反馈争议与再约草稿，测试中的合成时间现在通过调整隔离活动记录表示，不再向结项命令传入替代时钟。

更新后的微信开发者工具 `wechatide` 0.3.11 使用测试号、本地开发身份和隔离库 `.data/completion-clock-20260926`。先在隔离数据中将已成局合成活动 `511fef88-673d-473a-b0c8-435c92383d32` 的开始与结束时间移到过去，再在模拟器活动页实际点击“实际举办”、输入人数 4、点击“活动结项”。页面回读 `COMPLETED`，服务端 `/events/{id}/outcome` 回读 `held=true`、`actualCount=4`、`level=HOST_ONLY`、`independentFeedback=0`，见[模拟器截图](wechat-completion-clock-2026-09-26.jpg)。这说明主办方结项没有冒充独立参与者确认。验证后本地 API 已停止。

此记录只证明本地数据库和模拟器路径；活动时间为隔离合成数据，不能作为真实举办证据。正式微信身份、真机操作、现场签到及参与者独立反馈仍待验。

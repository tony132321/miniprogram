# T32 普通资料到期处置：代码级证据

范围：仅在负责人批准的用途级策略同时给出 `ordinary_profile.approved_days` 和 `approved_trigger=DELETE_EXECUTION` 后，按持久删除标记的最早 `recordedAt` 计算期限。旧策略缺少该明确触发条件时跳过自动处置，继续保留人工复核状态。测试策略的 1 天仅用于合成数据，不是产品保存期决定。

执行条件：用户已停用、DELETE 保护已执行、共享活动去标识及争议/必需记录隔离结果已记账，并且删除标记中的申请、用户和策略哈希相符。执行事务先锁用户行，再读取申请与执行记录。每个申请的 `privacy_ordinary_profile_expiries` 账本只写一次，记录策略哈希、标记时间、到期时间、数量和执行者。恢复重放按同一标记重新运行，已执行时保持幂等；同申请重复标记取最早时间，冲突身份使 sweep 失败。

已分类处置：删除会话、短时导出凭证、活动别名和当前通知同意偏好；清空通知 `detail`，把通知接收人替换成申请绑定的不可登录墓碑 ID；同活动别名同意历史去掉原用户直连。数据库 0065 迁移禁止真实 `users.id` 使用通知墓碑前缀，且在用户行锁之后阻止通知接收人/详情和通知同意偏好被写回；通知的供应商回执及外部状态仍可对账更新。

保留与待复核：停用的用户记录、通知行及供应商发送元数据、同意历史、共享活动安全关联、审计和不透明 JSON/自由文本继续保留。执行结果是 `PARTIALLY_PURGED_REVIEW_PENDING`，清单仍含用途和法定依据复核项。运营影响清单及删除 dry-run 保持原通知计数含义（原用户 ID 当前直连行数），另提供申请账本中的墓碑通知行数和分类处置数量，以便恢复后继续追踪。没有声称完整删除、外部副本删除或真实生产策略批准。

验证：全新已迁移 PGlite 库中，前后对照测试覆盖到期门槛、保留字段、数据库防回填、允许供应商回执更新、幂等和非运营身份拒绝；恢复测试从删除前备份重放最早标记，确认恢复完成即已处置，随后 sweep 为零。命令：`node --import tsx --test test/privacy-profile-expiry.test.ts`。真实外部标记服务、正式策略及生产备份恢复仍需目标环境验证。

# 举报首次响应目标配置

`REPORT_RESPONSE_POLICY_JSON` 为可选的运营配置，按四种举报类别指定默认严重度，并分别指定 `HIGH`、`NORMAL` 的首次响应目标分钟数。格式为：

```json
{
  "defaultSeverityByKind": {
    "SAFETY": "HIGH",
    "CONTENT": "NORMAL",
    "ATTENDANCE": "NORMAL",
    "OTHER": "NORMAL"
  },
  "targetMinutesBySeverity": { "HIGH": 5, "NORMAL": 120 }
}
```

上述分钟数仅用于合成测试，不是已承接的服务承诺或供应商报价。正式值守人员应先确定可执行的分级和响应目标，再由部署密钥管理系统注入配置。缺少配置时新工单标为 `UNCLASSIFIED`，不生成截止时间；安全运营关注队列会显示“未配置目标”。无效配置在进程连接数据库前被拒绝。

目标时间以数据库记录的工单创建时间计算。安全运营可逐单填写理由并改为 `HIGH` 或 `NORMAL`；请求须携带从待分配列表或逐单核查取得的 `expectedSeverity`，若工单严重度已变则返回 409，要求刷新复核。尚未首次响应的工单按新级别重新计算原创建时间起的目标，不重启计时；已经逾期的 `HIGH` 工单在首次响应前不能降级。已经首次响应的工单允许改级以指导后续处置，但原目标时间、首次响应时间和处理人保持不变，历史逾期可由这两个时间核查。改级审计保存旧、新严重度、目标分钟数、截止时间、数据库变更时间和理由。分配和状态变更也分别审计。普通 `REPORTS` 处理员只能操作分配给自己的工单；`SAFETY` 的首次响应关注队列只返回元数据，不返回举报正文。

具名处理员把工单标为处理中或直接结案时，服务端在同一事务中记录首次响应时间和账号，并向举报人生成站内通知。这是本地工作流留痕，不证明真人已在约定时间内响应、外部通知已送达或 15 分钟／24 小时服务目标已被团队承接。

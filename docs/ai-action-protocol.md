# T30 AI 动作协议：隔离测试边界

当前可执行的 AI 动作协议仅在 `createApp(..., { environment: 'test' })` 的隔离测试环境开放。`development` 和 `production` 对 `/ai/actions...` 返回 `FEATURE_DISABLED`；生产 `ai_draft` 开关仍为关闭状态。没有真实模型工具适配器、小程序审批 UI 或正式供应商调用，因此本地测试不构成真实模型验收。

## 动作与审批

- `POST /ai/actions:prepare` 接收类型化 `SAVE_DRAFT` 或 `PUBLISH_EVENT` 提议。服务端从已认证会话取得 actor，忽略请求中自报的角色和身份；只允许本人已有草稿及当前版本。`SAVE_DRAFT` 只接受模型建议字段白名单，不允许模型确认场地、代选主办席位、变更公开范围或报名方式；`PUBLISH_EVENT` 的完整 payload 必须等于数据库当前草稿。
- 提议记录 actor、活动、动作、预期版本、规范化内容 SHA-256、五分钟数据库时钟有效期及状态。`POST /ai/actions/:id/approve` 由本人明确提交 `approved: true` 和所见内容哈希；`POST /ai/actions/:id/revoke` 撤回。变更身份、内容、活动版本、期限或状态都拒绝执行。
- `POST /ai/actions/:id/execute` 逐项复核后，在同一数据库事务中复用现有 `updateDraft`/`publishEvent` 领域核心、写入业务审计、消费审批并持久化回执。仅提交成功返回 `SUCCEEDED`、真实审计 `actionId`、活动新版本、实际变化及待审核事项。重放同一幂等键返回原回执；换键不能重复执行。领域动作失败时事务回滚，审批仍未消费且无成功回执。
- 这组 HTTP 路由是合成协议测试夹具；未来实际接入时，模型工具不能获得 `approve` 能力，本人批准必须由独立可信交互提供。当前没有这种生产交互，因此不得开放生产执行。

## 模型上下文

`buildAiEventContext` 先取得活动版本读锁，再检查成员权限；只考虑本活动当前版本、已审核的最多十条公告。其中仅双行 `问：…` / `答：…` FAQ 且未命中联系方式筛查的公告进入上下文，附来源 ID、版本和 `UNTRUSTED_CONTENT` 标记。事件字段按白名单取值；含联系方式或联系线索的自由文本字段直接省略。提供方输出边界遮盖常见手机号、邮箱、微信号和 QQ 号，但正则不能保证识别任意写法。不返回邀请口令、成员名单、其他活动、待审公告或举报细节。公告正文仍是用户内容，不能当作系统指令；真实模型提示模板、数据处理审核和模型攻击评测仍需供应商接入后单独验证。

新建的审批记录进入本人数据导出与运营隐私影响计数。删除、保留期限和适用的 AI 内容标识仍需经具体法律及运营策略批准；当前未推断这些策略。验证使用合成账号和隔离数据库，见 `test/ai-actions.test.ts`。

# Wave 71 紧凑通知中心、只读实时看板与分享背景

用户要求复刻全部原稿、接通现有功能、并行开发、逐批上传 GitHub，并明确不要全量测试。延续 Wave 70 的既有工程；本计划不改变外部资源待验范围。

## 入口决定

N2 与 `_5` 原 HTML 没有来自其他屏的入口。root 已询问可选布局偏好，并给予答复时间。用户原有“全部 UI 页面和跳转页面”授权继续适用；目前按全部保留处理，通过相应页“更多”菜单进入，若用户后续选择只保留一种则调整。此为实现所需的默认导航决定，不能将未答复写成用户批准了某一布局。

- 通知中心默认继续使用 N1。其“更多”菜单保留通知设置入口，并增加“紧凑通知中心”切换；N2 可切回“卡片通知中心”，共用真实通知与审批数据和现有账号、版本、分页、失效检查。不新建通知后端、不制造支付或送达状态。
- 活动“更多”菜单仅对当前 READY 且真实主办身份开放“只读实时看板”。新增独立 `hostMonitorSection` 并在 section 资格、加载后校验和账号切换处理中保护。直接链接和陈旧菜单回调均不能绕过主办权限。返回工作台不丢原审批、公告、签到及结项能力。
- PG06-S 只在现有 share 页面弹层打开时恢复 PG06 来源背景。关闭后原 `_3` 分享卡保持；复用已授权的当前 event 只读字段，不在背景泄露邀请码、具体地址或不存在的头像、支付数据。

## 并行所有权

event/messages 的后续任务在 Wave 70 对应产品冻结与 immutable Git archive 建立后分派。独立 share 背景 scope 可在首页已冻结、等待独审期间提前执行；它以 Wave 69 immutable share 产品和 root QR 单行导入迁移例外为基线，root 显式排除 Wave 71 改动，不混入 Wave 70 提交或隔离测试工程。本批独立文件由三个 owner 并行，root 负责独立复核、共享资源、Git、微信 CLI/SDK/CUA、总矩阵。

1. Messages owner：messages WXML/WXSS、必要最小 JS 入口、准确资源、来源/实施证据。保护 INBOX、N1、关闭私聊及原审批/通知方法。
2. Activity owner：event WXML/WXSS、必要最小 JS section/菜单资格、准确资源、来源/实施证据。保护所有现有 section，特别 Wave 70 PG07、成员与主办详情及 Wave 69 PG06/08/09。
3. Share owner：share WXML/WXSS、分包准确资源、来源/实施证据。JS/JSON与现有弹层前景保护；不迁移 canvas、令牌生命周期或分享 intent。

完整来源输入为 `docs/evidence/caper-next-unrouted-and-background-gap-audit-wave70-2026-10-02.md` 和解压后的原 HTML/PNG，不能把早批限定审查视为新屏完成证明。按有效 CSS、实际 FILL/字重轮廓和准确原图恢复，所有动态值来自当前 API。没有真实照片字段的人像使用匿名字形；地图原图只能明示为原稿示意，不宣称实际定位/导航/订场/支付。

仅对新导航行为编写必要的权限/陈旧回调/返回测试，不为纯样式写照搬实现的测试。每 owner 一次 source/绑定/旧范围保护检查；修正后只复查实际差异。root 对三新状态与真实同 ID 跳转做短分段 SDK 检查，最终 CLI 编译与包体门禁；不跑全量业务、全量页面或 CI。Mac 锁屏期间不声称 native computer use 点击已通过。

main 体积使用本批最终 CLI 实测，不凭历史余量估算通过。优先复用已证明同字节的 glyph 与所属分包图片，保留准确图片质量，不扩全局字体。代码及证据提交 `[skip ci]`，上传 immutable Git 对象并核实远端 head/tree。所有剩余普通长页原稿差距、真机与外部资源单列，未完成前目标保持 active。

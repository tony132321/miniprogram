# Project IRL R1 功能实现规格

## 目的与依据

本规格以 `/Users/tsb/Downloads/01_PRD_v1.0.md` 的 R1 条款为产品基线；`AI_IRL_PRD_v1.0 (1).docx` 是相同业务规则的排版版。`06_Agent_Handoff_Prompt.md` 仅作为工程交接参考。用户本轮要求先跑通功能，暂不自行设计视觉 UI。

目标用户是已有球友与微信群的成年人主办方。首个活动模板是公共商业场所的室内羽毛球。完成标准是至少四个独立真人账号依次经历建局、主动分享、报名、一人退出与候补、成局或取消、到场证据、结项和再约。测试数据不能冒充真实试点。

## 范围

R1 包含最小身份与授权、手动建局、结构化 AI 草稿适配、活动版本、邀请凭证、报名审批、主办方预留、FIFO 候补、成局和重大变更、站内通知与授权后的外部通知、公告问答、签到、费用记录、再约、运营工单、隐私请求、审计和服务端指标。页面只做清楚可用的基础布局与状态提示。

R1.1 的公共发现和陌生人匹配、R2 的收款退款和商户库存、语音识别、照片相册、自动建群、自动订场均不纳入本次实现。功能开关默认关闭这些能力，服务端同样拒绝调用。

## 系统结构

原生微信小程序负责展示与用户动作；Web 运营端负责受限的工单、活动审查和失败任务处理。一个 TypeScript 模块化 API 服务承载全部业务规则，关系数据库为唯一活动事实来源。数据库事务结束后由 outbox 和持久任务执行外部通知。AI、微信登录、通知和内容审核通过适配器接入。未配置的适配器返回明确的 `UNAVAILABLE`，不得返回虚假成功。

本地开发可以使用持久化 PGlite，以便在无独立数据库服务时跑通功能。生产适配器使用独立 PostgreSQL；PGlite 的单连接特性不能代替生产并发验证。生产部署前必须在真实 PostgreSQL 中重跑并发与恢复测试。任何本地开发身份入口只能在显式开发配置下启用，生产配置启动时拒绝开发身份入口。

## 领域契约

- `Event` 保存当前状态与版本号；`EventVersion` 保存已发布字段的不可变快照。时间使用 UTC 存储并带活动时区；人民币金额用整数分。
- 活动状态为 `DRAFT → RECRUITING → CONFIRMED → IN_PROGRESS → COMPLETED`，并可按规则进入 `EXPIRED` 或开始前 `CANCELLED`。审核、招募开关和成局风险分别记录。
- `Registration` 的有效状态包括 `REQUESTED`、`INTERESTED`、`WAITLISTED`、`OFFERED`、`CONFIRMED`、`RECONFIRM_REQUIRED`；终态为 `CANCELLED`、`EXPIRED`、`REJECTED`、`REMOVED`。每活动每用户至多一个有效报名主体，历史转换写审计。
- 容量占用为已确认席位、重新确认保留席位、有效补位邀请和未过期预留之和，始终不超过上限。待审批、待定及普通候补不占位。只有确认报名人数可计入成局人数。
- 影响容量的命令锁定活动行，检查 `expected_version`，在同一事务内执行状态修改、容量校验、审计与 outbox 写入。相同 `actor + route + idempotency_key` 返回同一业务结果。HTTP 409 表示版本冲突。
- 退出释放席位后按候补创建单个有期限的 offer。offer 需要本人确认；到期任务和确认竞争以事务中的当前状态为准。普通候补按进入时间 FIFO；AI 不排序。
- 重大变更创建新 `EventVersion`，将已确认报名转为 `RECONFIRM_REQUIRED`，暂停招募。旧同意、旧报名、旧通知授权不能替代新版本确认。活动开始后不能通过普通取消抹去历史。
- 站内通知是可靠的基础渠道。外部通知状态区分待发送、提供方已受理、失败、用户打开；“已受理”不能表述成送达或已读。撤回通知授权后不再新发送。
- 动态签到码短时有效并绑定活动，服务端检查报名与时间窗口。扫码、人工补记、参与者确认和争议为不同证据。结项不自动等于可信完成。
- AA 只记应分摊、主办方收款标记与参与者处理标记，不存储平台支付成功状态。再约复制模板字段生成新草稿，不复制报名、费用或授权。
- 举报、申诉、隐私请求和危险后台操作须记审计；后台只能读当前工单或活动所需的最小资料。
- AI 只输出结构化草稿或说明；服务端逐字段校验日期、人数、费用、地点和授权。AI 不直接修改业务表，也不执行任意 SQL。模型不可用时手动路径完整可用。

## 验收与发布边界

每个 R1 需求映射到自动化测试：状态机、对象级权限、重复请求、100 次竞争最后席位、候补超时重放、重大变更、通知拒绝与失败、签到争议、AI 格式错误和降级。另以最小功能页面进行小程序开发者工具与真机检查。无法执行的外部或真机测试必须标明未验证。

本地功能完成不等于公开发布。真实 AppID、主体与类目、通知模板、域名、数据处理方案、值守人员、真实设备及至少三场受控活动证据，是独立发布闸门。当前这些材料均未提供，不得将演示配置、模拟回执或测试用户算入生产事实。

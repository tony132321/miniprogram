# Project IRL R1 功能原型

这是按照 `01_PRD_v1.0.md` 构建的本地可运行原型。首个场景是已有球友的室内羽毛球活动。小程序页面只提供完成流程所需的表单和状态，没有进行视觉 UI 设计。

## 已接通的本地流程

主办方保存并编辑草稿、检查字段、发布邀请；球友各自报名、待定或申请；主办方预留可认领席位；满员后按进入时间候补，退出时产生限时补位邀请。服务端处理活动版本、重大变更预览与本人重新确认、成局、截止时间检查和取消。活动成员可提交问题，主办方可提交公告和回答，运营人员人工审核后对成员可见；当前版本中能确认的时间、场地和费用可由保守规则回答，未知问题进入人工审核与主办方待办。现场动态二维码与扫码签到、人工补记本人确认、独立结项反馈、AA 分摊记录、再约草稿、举报、申诉、本人数据 JSON 导出与隐私请求均有接口和最小页面。

主办方若希望公告直接回答活动事实，可在一条公告中写 `问：需要自带球拍吗？`，换行写 `答：请自带球拍。`。运营审核通过后，同一活动当前版本的成员输入完全相同的问题可得到附公告来源的回答；自由文本公告仍不会被自动解释，活动改版后需重新发布并审核该问答。AA 费用记录以整数分分摊；主办方修订金额会创建新版账单，旧版双方标记仅作历史，当前金额需要各方重新确认。

受控公开活动提交后进入人工审核；审核通过前不会开放招募或向陌生人展示详情。公开活动必须逐一审核报名。活动公开信息修改后需要按新版本再审；重大变更要求参与者重新确认，运营审核通过也不会覆盖这一暂停。运营工作台可以查看待审活动的主办方与活动事实并填写结论。当前没有真实内容审核或主办方资质核验服务，正式公开发布仍受上线闸门限制。

外部消息在发送前检查用户同意、活动版本和当前状态。站内通知始终保留。当前没有微信订阅消息供应商配置，因此外部状态显示 `UNAVAILABLE`；接入适配器时只记录提供方已受理，不代表送达。运营台的“通知待跟进”列出外部发送不可用且用户尚未打开站内通知、或外部结果不确定的消息；“最近已跟进”可复核处理说明、处理人和时间。人工跟进留痕不会改写外部发送状态，也不会声称用户已收到。AI 未配置模型，入口明确显示规则提取降级；手动建局不受影响。

运营台的“试点指标”仅向 `METRICS` 权限开放，按活动发生地时区统计有到场和独立反馈证据的每周完成活动数；活动结束后才进入到期样本，并显示证据支持的保守完成率、待复核数及已完整观察 28 天的主办方复用率，以及以本人扫码或已确认人工补记的活动时间为起点的 30 天再参与率。D30 在不足 100 名成熟用户、首场参与尚待核验，或待结项再次签到可能改变结果时不判断 25% 参考线。不到 100 场到期样本不评估证据口径的 70% 参考线；待复核场次可改变结论时保持未定，该数值不单独决定发布闸门。公开活动提交人工审核时尚不算发布；首次审核通过后才起算复用观察窗及 WQCA 的发布最低人数。`PILOT_USER_IDS` 明确列出的已核验试点用户才可进入统计；含未列名报名者的活动排除，名单为空时所有活动都不计入。旧活动与本地开发活动默认标为测试。具备独立 `SUPPORT_MINUTES` 权限的运营人员可按活动记录直接人工分钟并查阅最近 100 条记录；只读 `METRICS` 权限不能写入。报表只显示已记录总量与活动覆盖数，标明记录不完整，未记录不等于零。当前 AA 费用只是双方声明，缺少实际收入及完整直接成本来源，贡献利润显示“不可计算”；报告反映读取时的争议处理状态，不能当作任意历史时点的重放结果。

运营报表另列候补补位邀请的接受、过期、取消和未到期数量；确认率只用已接受与已过期的成熟邀请，不代表消息送达或现场到场。成局耗时取首次可访问发布到首条成局审计的中位分钟数，与主办方实际协调分钟分别记录。

服务端核心活动动作在迁移 12 后由数据库事务同步写入脱敏业务事件；字段、成功口径及当前覆盖范围见 [`docs/business-event-dictionary.md`](docs/business-event-dictionary.md)。公开活动只有审核通过才产生 `ACTIVITY_PUBLISHED`；这张事件表不承载用户内容，也不代替试点指标的独立证据核算。

## 本地运行

已在 Node.js 24.19.0、pnpm 11.19.0 下运行。安装依赖后启动：

```bash
pnpm install
DEV_AUTH=1 OPERATIONS_USERS=ops pnpm start
```

API 默认监听 `http://127.0.0.1:3000`。`GET /health` 只检查进程存活；部署就绪探针应使用 `GET /ready`，该接口实际查询数据库，数据库不可用时返回 `503`，不对外暴露错误详情。探针自身应配置超时；此接口不代表微信、通知供应商或后台任务已完成。本地数据保存在 `.data/pgdata`；停止再启动后会保留。`DEV_AUTH=1` 只供本地多账号测试，生产模式会拒绝它。

在微信开发者工具中打开仓库根目录的 `project.config.json`。当前配置为本机测试号 `wxbbcab69099026d3f`，仅用于模拟器调试；正式环境须换为实际小程序 AppID。`miniprogram/config.js` 默认指向本机 API，开发者工具的本地测试可以使用；真机和正式版本需要合法 HTTPS 域名，并清空 `developmentUser`。

本地试流程：使用 `host` 创建未来时间的活动，勾选本人参加及已核实场地；发布后在“我的活动”打开详情。使用“我的”切换 `p1`、`p2`、`p3` 分别报名，回到主办方确认成局。再增加候补，退出一个席位并由候补主动确认。活动内容提交后，可在 `http://127.0.0.1:3000/ops` 输入开发运营账号 `ops` 审核。签到时间窗为活动开始前 30 分钟至结束后 30 分钟；主办方展示自动更新的二维码，参与者扫码或输入口令。断网后主办方可在 48 小时内申请补记，由参与者在 7 天内确认，记录为不同的证据类型。开发者工具模拟器中的二维码绘制、图像解码及 mock 扫码已验证；真机相机扫码尚待验证，详见 `docs/evidence/wechat-devtools-2026-09-24.md`。

运行验证：

```bash
pnpm test
pnpm typecheck
pnpm preflight:release
```

`preflight:release` 检查小程序静态配置并在本机开发设置仍不适合发布时返回非零状态。当前开发配置预期不通过；即使静态检查通过，仍须核实微信后台域名白名单、真实 AppID、网络请求与真机交互。

## 部署边界

公开发布前按 [R1 发布闸门核对](docs/release-gates-2026-09-25.md) 逐项补齐真实主体、微信能力、个人信息、值守、真机、目标环境及真人受控活动证据；本机原型和测试号不构成放行依据。

本地 PGlite 备份恢复演练：先停止 API，再运行 `pnpm exec tsx scripts/local-backup.ts backup .data/pgdata .data/local-backup.tgz`；用 `pnpm exec tsx scripts/local-backup.ts restore .data/local-backup.tgz .data/local-restored` 恢复到全新目录。命令拒绝覆盖已有备份或恢复目录，恢复时会验证迁移校验值。备份文件包含完整业务数据，应限制访问并妥善保管。此工具只服务本地 PGlite；生产 PostgreSQL 需要单独的备份策略和恢复演练，记录见 `docs/evidence/local-backup-2026-09-24.md`。

独立 PostgreSQL 验证可运行 `IRL_PG_TEST_URL=postgresql://USER@127.0.0.1:PORT/irl_r1_test_NAME pnpm exec tsx scripts/verify-postgres.ts`。目标必须是本机、名称以 `irl_r1_test_` 开头且没有业务表；脚本会创建活动并发起 100 个真实数据库连接池上的抢位请求，不用于已有数据的数据库。第 39 版旧状态到第 42 版迁移另用全新空库运行 `scripts/verify-postgres-history-upgrade.ts`。本机迁移、并发及恢复证据见 `docs/evidence/postgres-latest42-2026-09-27.md`。

本机 HTTP 混合负载基线可对另一个全新空库运行 `IRL_PG_TEST_URL=postgresql://USER@127.0.0.1:PORT/irl_r1_test_NAME pnpm exec tsx scripts/benchmark-http.ts`。脚本以 20 RPS 持续 30 秒读取公开活动和本人活动、写入草稿，并报告错误数与 p50/p95/p99；仅用于本机验证，见 `docs/evidence/local-http-load-2026-09-25.md`。

运营举报队列优先列出未结案安全类工单，再列其他未结案工单，支持每页 100 条继续加载；`SAFETY` 只是举报类别，不代表人工确认严重性或已提供响应时限。详见 [`docs/evidence/report-triage-2026-09-25.md`](docs/evidence/report-triage-2026-09-25.md)。

生产模式使用 PostgreSQL，要求 `DATABASE_URL`、`CHECKIN_SECRET`、真实 `WECHAT_APP_ID` 和 `WECHAT_APP_SECRET`；缺项会在数据库连接前阻止启动。运营工作台 `/ops` 从部署密钥管理系统注入 `OPS_ACCOUNTS_JSON`，其中每人有独立的账号、密码校验值、动态验证码种子和显式权限。例如 `[{"username":"moderator","passwordHash":"scrypt$…","totpSecret":"…","permissions":["REPORTS","CONTENT","JOBS"]},{"username":"reviewer","passwordHash":"scrypt$…","totpSecret":"…","permissions":["APPEALS"]}]`。生产启动至少要求两个独立账号，覆盖 `REPORTS`、`CONTENT` 和 `JOBS`，并保证每位举报结案或内容审核人员都有另一位具 `APPEALS` 权限的复核人。可授予的权限为 `REPORTS`（举报）、`SAFETY`（活动暂停）、`EVENT_REVIEWS`（公开活动审核）、`APPEALS`（申诉）、`PRIVACY`（个人信息请求）、`CONTENT`（内容审核）、`RATE_LIMITS`（异常请求）、`NOTIFICATIONS`（通知人工跟进）、`METRICS`（只读试点指标）、`SUPPORT_MINUTES`（记录与查看人工分钟）、`JOBS`（失败任务恢复）。每个运营读写接口都在服务端校验对应权限；未授权队列不会返回数据。同名账号、共用验证码种子以及缺少、未知或重复权限均在启动时被拒绝。既有的 `OPS_USERNAME`、`OPS_PASSWORD_HASH`、`OPS_TOTP_SECRET` 单账号配置仅供开发环境兼容，不能与账号列表混用。运营人员用账号、密码和认证器生成的 6 位动态验证码登录；令牌 12 小时过期，可主动退出。验证码允许前后各一个 30 秒时间窗的时钟偏差，每个账号的每个计数器只能使用一次；来源 IP 和账号各限制每分钟 10 次登录请求。密码仅保存 scrypt 校验值，令牌仅保存 SHA-256 摘要；动态验证码种子仅在受控人员的认证器和密钥管理系统中保存。

候选和生产阶段还要求已核查的用途级 `RETENTION_POLICY_JSON`，格式见[保留策略配置](docs/retention-policy-contract.md)。开发包中未批准的提案会被拒绝；格式通过仍不能替代删除执行与恢复演练。

举报首次响应的默认严重度与目标分钟数可通过 `REPORT_RESPONSE_POLICY_JSON` 配置，格式及实际能力边界见[首次响应目标配置](docs/report-response-policy.md)。未配置时工单仍可提交，但安全运营队列会标出缺少目标；界面不宣称服务时限达成。

初次配置可在可信终端生成一组新凭据（命令不会把密码作为进程参数）：

```bash
read -s 'operator_password?请输入至少 16 字的临时运营密码：'
printf %s "$operator_password" | pnpm exec tsx scripts/enroll-operator.ts reviewer
unset operator_password
```

为每位运营人员分别运行初始化命令，将各自的 `OPS_TOTP_SECRET` 录入本人认证器，再把生成的三项值加上经负责人确认的 `permissions` 转换为上方 JSON 对象并安全保存到部署密钥管理系统。账号从配置中移除或更换其密码校验值、验证码种子、权限后，服务重载时旧会话失效；其余账号不受影响。命令输出含登录种子，不要提交到仓库、工单或普通日志。代码已支持个人独立账号、按功能限权和逐人操作审计；正式值守还需要真实人员发放、设备遗失恢复、账号撤销流程、权限分工与实际排班验证。内容审核、举报和值守不能在无运营人员时自动声称完成。数据库启动会在事务中记录版本 1–42 的迁移及各自校验值；已应用的 SQL 不能直接改动，后续表结构要新增迁移文件和 `src/db.ts` 中的版本登记。正式部署前仍需在目标 PostgreSQL 环境演练备份恢复和跨连接并发。

主办方可在活动详情页按本场授予报名审批、公告与回答、签到管理权限，并即时撤回。协办的管理请求每次按当前活动授权检查；撤权不影响其自己的报名和签到。授权、撤权、旧会话拒绝及微信开发者工具模拟器流程见[协办权限验证](docs/evidence/cohost-grants-v31-2026-09-26.md)。

微信登录 code 经提供方验证后，服务端在签发会话的同一事务里记录其 SHA-256 摘要，24 小时后清理旧摘要；同一有效期内的重放和并发复用不能产生第二个会话。真实 code 过期仍由微信提供方判定；本地适配器测试不代替真实提供方验收。见[登录重放验证](docs/evidence/wechat-login-replay-v31-2026-09-26.md)。

后台任务重试五次仍失败时进入运营台“失败任务”队列。具 `JOBS` 权限的运营人员可查看受限错误类别并审计地重新排队；这只表示等待后台再次处理。外部通知状态不确定时必须先在通知跟进队列人工核对，不能通过重新排队重复发送。处理流程和验证见 [`docs/evidence/failed-job-recovery-2026-09-25.md`](docs/evidence/failed-job-recovery-2026-09-25.md)。

活动 `is_test` 标记由服务端决定。迁移前已有活动保守标为测试，开发身份创建的活动始终是测试。生产模式下，发起、发布及参加受控活动的请求必须由 `PILOT_USER_IDS` 中的内部用户 ID 发出；名单为空时默认拒绝这些新增动作，已存在参与者仍可退出，举报和隐私请求仍可提交。微信登录只能验证账号控制权，不能证明成年；名单必须在服务外完成成年身份与试点资格人工核验后配置，不能用用户自报或勾选框生成。仅名单中主办方新建的活动可进入正式指标候选；含名单外账号报名者的历史活动仍被排除。再约草稿继承来源活动标记，客户端请求不能修改该标记。此门禁的本地证据见 [`docs/evidence/adult-pilot-gate-v31-2026-09-26.md`](docs/evidence/adult-pilot-gate-v31-2026-09-26.md)。

数据库原子限流覆盖报名相关操作（每账号 20 次/分钟）、建局与发布（每账号 10 次/小时）、举报（每账号 10 次/小时）、活动详情读取（每账号 120 次/分钟）、微信登录（每来源 IP 10 次/分钟）和邀请口令查询（每来源 IP 60 次/分钟）。超限返回 `429` 与 `Retry-After`，最近 24 小时的拒绝记录供运营查看；限流记录保留 7 天。退出报名不受报名限流影响。默认只用直连 IP，忽略客户端自带的 `X-Forwarded-For`；若生产环境由可信反向代理转发，可设置 `TRUSTED_PROXY_IPS` 为代理的实际 IP（逗号分隔），并要求代理覆盖或追加真实来源地址，避免伪造。正式部署仍需按实际流量和代理拓扑验证阈值。

微信开发者工具模拟器已跑通一条跨身份活动流程，但真机验收、真实模型、消息模板和回执、成人试点核验、隐私请求执行策略、商用域名、类目/主体审核、真实活动试点尚未完成；不要把测试账号或模拟结果当成上线证据。R1 的费用页只记录双方声明，不处理支付或代收。

逐项状态与缺口见 `docs/acceptance-matrix.md`。实现规格和执行计划在 `docs/superpowers/`。
